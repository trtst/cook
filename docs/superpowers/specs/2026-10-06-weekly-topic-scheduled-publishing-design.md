# 周刊专题定时发布设计

## 背景与目标

后台目前只能创建未上架专题，再手动上架或下架。周刊详情页的 `topic-summary__meta` 显示专题类别和期数，没有本期日期范围。

本设计为周刊专题增加定时发布，并在小程序专题详情展示发布时间之后的下一个完整自然周。预约发布时间是日期周期的唯一基准；实际 Worker 执行延迟不改变所显示的周期。

## 已确认的产品规则

1. 周期为预约发布时间所在自然周之后的完整一周，按北京时间周一至周日计算。例如预约于 2026-10-06 发布，显示 `10-12 至 10-18`。
2. 周刊继续使用 `LISTED / UNLISTED` 状态。预约中的专题保持 `UNLISTED`，到预约时间后自动转为 `LISTED`。
3. 专题创建并保存后可预约未来时间。预约可以调整或取消；取消后专题保持未上架。
4. 编辑已预约专题时保留预约时间。手动立即上架会清除预约，避免到期任务再次生效。
5. Worker 上架时以预约时间写入 `publishedAt`。因此处理延迟不会移动周刊周期。
6. 周刊使用自己的定时发布 Worker 开关，不改变知识文章定时发布循环。

## 方案选择

### 推荐：未上架状态加预约时间

在 `HomeTopic` 上增加可空 `scheduledPublishAt`。是否预约由该字段表达；专题可见性仍只由现有 `status` 表达。Worker 仅处理 `UNLISTED` 且预约时间已到的专题。

- 优点：不复制可由预约时间推导的状态；前台可见性规则保持简单；取消预约无需新的状态转换。
- 成本：后台需在未上架状态旁展示预约时间，并提供预约/取消操作。

### 不采用：新增 `SCHEDULED` 状态

新增状态可直接表达后台预约标签，但预约时间字段仍然必需，而且需要更新所有状态 DTO、后台排序与状态转换；状态与预约时间也可能不一致。

### 不采用：复用知识文章预约接口与开关

文章与周刊具有不同的资源状态、写入 Service 和公开发布查询。两者共享 Worker 运行环境，但分别配置开关和扫描逻辑，避免文章开关意外启停周刊发布。

## 页面行为

### Admin 周刊列表与编辑页

- 仅已保存专题提供预约操作；预约时间由后台按北京时间选择，必须晚于服务端当前时间。
- 未预约的未上架专题可预约；已预约专题显示预约时间，并可调整或取消。
- 保存已预约专题的标题、介绍、封面和菜谱时保留当前预约时间。
- 手动立即上架会清除预约时间；已上架专题不能继续预约。
- 预约、取消、立即上架均刷新专题版本，使用版本号避免覆盖并发修改。

### 小程序周刊详情页

- 在 `topic-summary__meta` 左侧保留推荐类别和期数标签，最右侧显示本期日期范围。
- 日期范围由 API 返回，页面不依据设备时区自行推算。
- 公开专题只在状态为 `LISTED` 后可见；预约中的专题不进入当前专题或往期列表。

## 数据与接口

### 持久化事实

- `home_topics.scheduled_publish_at TIMESTAMPTZ NULL`：仅表示尚未执行的预约时间；取消或成功发布后清空。
- 新增前向 migration 和到期扫描索引 `(status, scheduled_publish_at)`。
- 不持久化周期起止日期；该范围可由权威 `publishedAt` 与固定北京时间规则推导。

### Admin API

- 新增 `POST /admin/home-topics/{topicId}/schedule`。
- 请求体提交 `scheduledPublishAt: IsoDateTime | null` 和 `expectedVersion`；`null` 表示取消预约。
- 写请求要求数字字符串 `Idempotency-Key`。服务端只允许对 `UNLISTED` 专题预约，拒绝过去时间、版本冲突和不满足现有专题发布条件的记录。
- Admin 专题列表与详情响应增加 `scheduledPublishAt`，供后台展示当前预约并进行后续操作。
- 预约、取消、立即上架及自动上架写入管理员/系统审计记录。

### 公开专题响应

- `HomeTopicDetail` 增加 `periodStartDate` 和 `periodEndDate`，均为北京时间下计算出的日期字符串 `YYYY-MM-DD`。
- API 从 `publishedAt` 计算下一自然周的周一、周日。前端将两个日期格式化为紧凑的月日范围。
- `HomeTopicHistoryItem` 不增加周期字段，因为往期卡片不展示该范围。

## 定时执行与一致性

- 新增独立开关 `HOME_TOPIC_SCHEDULED_PUBLISH_WORKER_ENABLED`；不改变 `ARTICLE_SCHEDULED_PUBLISH_WORKER_ENABLED` 或 `WORKER_ENABLED`。
- Worker 定期扫描 `status = UNLISTED AND scheduledPublishAt <= now` 的专题。
- 上架事务仅在专题仍未上架且预约时间仍等于本次扫描值时生效；事务内将状态改为 `LISTED`、将 `publishedAt` 设为预约时间、清空预约时间、递增版本并写审计。
- 管理员取消或调整预约与 Worker 到期处理并发时，以条件更新保证只有仍有效的预约能上架。
- 事务失败时不清除预约；下一轮继续扫描重试，不新增 Outbox 消费类型。
- 手动立即上架的事务同时清空 `scheduledPublishAt` 并设置 `publishedAt` 为当前时间。

## 失败与权限行为

- 服务端校验管理员身份、目标专题状态、未来预约时间、`expectedVersion` 和幂等键。
- 预约冲突返回版本冲突错误；过期或不允许预约的状态返回明确业务错误。
- 预约中的专题不会因前端隐藏按钮而获得特殊权限；所有状态转换由服务端校验。
- Worker 未启用时不会执行预约；运行环境需单独启用周刊开关并观察 Worker 启动日志。

## 验收标准

1. 预约未来时间后，Admin 列表与编辑页显示时间，公开当前专题与往期列表仍不显示该专题。
2. 取消预约后，专题保持未上架；预约时间被清除。
3. 编辑预约中的专题后保存，预约保留；调整预约更新版本与时间。
4. 到期后专题自动上架、公开读取可见、预约时间清空，`publishedAt` 等于预约时间。
5. 延迟执行不改变周期；预约于周二 2026-10-06 的专题返回周期 `2026-10-12` 至 `2026-10-18`。
6. 手动立即上架清除预约，之后不会由旧预约再次处理。
7. 取消/调整与到期任务并发时不会重复上架或覆盖新预约；Worker 事务失败后可重试。
8. 日期范围在不同设备时区下保持北京时间周一至周日边界，并在 `topic-summary__meta` 右侧显示。
9. 周刊 Worker 开关与文章定时发布开关独立。

## 实施范围

- Prisma/API：字段与 migration、预约接口和 DTO、公开日期区间计算、审计、OpenAPI 与契约文档。
- Worker：独立开关、到期扫描、原子上架、重试日志与运行说明。
- Admin：预约/调整/取消入口、预约时间展示、版本和状态处理。
- Client：专题详情类型及 meta 右侧日期范围显示。
- 本期不新增 `SCHEDULED` 状态、手填周期起止日期、文章预约通用抽象、Outbox 类型或专题页面以外的发布日期展示。
