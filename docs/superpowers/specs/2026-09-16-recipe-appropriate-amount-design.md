# 菜谱“适量”模糊用量设计

## 目标

允许无法稳定量化的辅料、佐料使用唯一模糊用量“适量”，同时保持精确数量、系统单位、人数换算、购物合并和营养结果语义清晰。

## 数据语义

1. “适量”是菜谱食材关系上的模糊用量，不是系统计量单位，不进入单位表。
2. 正式菜谱用量允许两种互斥结构：
   - 精确：`{ kind: "EXACT", quantity, unitId }`。
   - 模糊：`{ kind: "FUZZY", text: "适量" }`。
3. 模糊用量只保留“适量”；已有“少许 / 按需”在读取或转换时归一为“适量”，新写入不再接受这两个值。
4. “适量”只允许当前系统分类代码为 `SEASONING` 的食材使用；不新增主体/辅料字段，命中真实食材后以其当前系统分类为准。

## 转 JSON

`recipe.import.v1` 的食材行增加必填 `fuzzyText`：

```json
{
  "name": "酱油",
  "quantity": "10",
  "unit": "毫升",
  "fuzzyText": null,
  "categoryCode": "SEASONING"
}
```

```json
{
  "name": "盐",
  "quantity": null,
  "unit": null,
  "fuzzyText": "适量",
  "categoryCode": "SEASONING"
}
```

精确行要求 `quantity + unit`，并令 `fuzzyText = null`；模糊行要求 `quantity = null`、`unit = null`、`fuzzyText = "适量"`，且 `categoryCode = "SEASONING"`。命中系统食材时使用其当前分类覆盖来源建议，再校验是否允许“适量”。来源中的“少许 / 按需 / 若干 / 酌量”等仅在食材确属 `SEASONING` 时归一为“适量”；来源已有明确数量时不得改成“适量”。

## 编辑交互

1. 小程序在用量选择面板中把“适量”作为独立的模糊用量选项，与系统单位分组展示。
2. 选择“适量”立即清空数量和精确单位，隐藏数量输入框。
3. 从“适量”切回任一精确单位时显示空数量输入框，原数量不恢复，并聚焦数量输入。
4. 后台创建、编辑和导入修正只提供“精确用量 / 适量”两种状态，不再展示“少许 / 按需”。
5. 草稿只保存当前分支的数据；发布时精确分支要求正数数量和有效系统单位，模糊分支只接受“适量”。
6. 已绑定 `ingredientId` 的食材名称只读；点击名称重新选择食材。更换为非 `SEASONING` 食材时清除“适量”，切回精确用量且不恢复旧数量。

## 下游规则

1. 人数变化只换算精确用量，“适量”保持不变。
2. 购物和冰箱缺口中的“适量”逐项展示，不与精确数量或其他模糊项做数值合并。
3. 营养计算跳过无法量化的“适量”食材；只要正文存在“适量”，营养状态最高为 `ESTIMATED`，不得为 `COMPLETE`。没有任何可计算精确食材时仍为 `INSUFFICIENT`。
4. 不新增数据库表、字段、单位种子或迁移。

## 兼容与验收

1. 历史正文、草稿或接口数据中的“少许 / 按需”读取时显示为“适量”，后续保存写回“适量”。
2. JSON 导入接受上述精确和模糊结构，拒绝同时填写两套值、缺失两套值或填写其他模糊文本。
3. API DTO、OpenAPI、API/Admin/Client 自有类型统一只公开“适量”。
4. 定向验证覆盖 JSON 解析、发布、营养降级、后台选项、小程序切换清空与三端类型检查。
