# 菜谱 Owner 与公共内容用户池设计

## 已确认的目标

1. 每一条菜谱都必须有一名 `owner`。用户创建、发布和改编后保存的菜谱，当前创建者就是 owner；用户推荐审核收录为灵感菜谱后，推荐者仍是该灵感菜谱的 owner。
2. 平台后台直接发布的灵感菜谱，从固定的 100 名公共内容用户池中随机选择一名 owner。该池后续也服务于需要“平台公共内容归属人”的计划、饭局等内容；它不替代真实参与人、操作者、权限人。
3. 菜谱在首次发布或生成时冻结 owner 昵称。用户后续改昵称不回写菜谱；详情中的“由 xxx 整理”读取该快照。空快照不显示署名。
4. 移除 `curatedByName`，不保留兼容输出或回退链路。
5. 删除所有旧的、没有 owner 的历史灵感菜谱；公共区域只继续显示满足灵感条件且有 owner 的菜谱。

## 数据事实与迁移边界

`users` 继续保存实时账户资料；菜谱自身保存 `owner_id` 与不可变 `owner_nickname_snapshot`。前者用于关系、权限和审计，后者仅用于历史展示，名称明确表达快照语义。

现有 `RecipeInspirationOwner` 改名为面向公共内容的池成员模型（例如 `PublicContentUserPoolMember`），保持单独成员表而不是在 `User` 上增加身份布尔值：成员资格有独立运营生命周期，且未来能以同一个池服务不同公共内容。成员必须恰为 100 名、状态为 `ACTIVE`；池的配置和选择都只在服务端与后台管理使用。小程序用户接口不返回成员资格；后台用户列表/详情返回只读 `isPublicContentPoolMember` 并展示该状态。

迁移分两阶段执行，防止用静默兜底掩盖脏数据：

1. 先输出待删除的旧灵感菜谱及其引用数量，目标固定为 `is_inspiration = true AND owner_id IS NULL`。上线操作前确认备份可恢复；在同一个受控迁移/运维步骤中删除这些菜谱及其依赖的浏览记录、收藏、计划/饭局引用、推荐收录指针等，不允许留下悬挂引用。
2. 删除完成后，迁移必须断言不存在任何 `owner_id IS NULL` 的菜谱。若仍有非灵感空 owner 行，迁移失败并停止，不能猜测归属或顺带删除。通过断言后删除 `curated_by_name`，新增 `owner_nickname_snapshot`，使 `owner_id` 变为非空外键，并将 Prisma `Recipe.owner` 改成必需关系。

`RecipeRecommendation.curatedByName` 同时删除。审核所需的展示名由来源菜谱的 `ownerNicknameSnapshot` 读取，不再复制一个整理人字段。

## 写入规则

- 发布草稿：创建者作为 owner，写入其当前昵称的 trim 后值（空值写 `null`）至 `ownerNicknameSnapshot`。
- 从灵感改编为私房菜：当前改编用户作为新的 owner，并冻结该用户当时昵称。
- 用户菜谱推荐审核通过：新灵感菜谱沿用推荐来源菜谱的 `ownerId` 与 `ownerNicknameSnapshot`，不再读取实时用户昵称，也不分配池成员。
- 后台直接创建和 JSON 导入发布灵感菜谱：在创建事务内从公共内容用户池均匀随机选择 active 成员，同时读取并冻结被选成员当前昵称。池不足、成员失效或昵称读取失败时返回明确冲突，不创建菜谱。

所有更新菜谱正文、标题、分类或重新审核的路径不得修改 owner 或 owner 昵称快照。不存在 owner 转移功能。

## 读契约与 UI

灵感详情 DTO 将 `curatedByName` 替换为：

```ts
owner: {
  uid: number;
  nickname: string | null; // Recipe.ownerNicknameSnapshot，不是 User.nickname 的实时值
}
```

如“我的菜谱”详情也有归属展示需求，使用同一字段和语义；不再从当前 session 的 nickname 拼署名。客户端详情页统一以 `owner.nickname?.trim()` 生成 `由${name}整理`，名称为空则不渲染。列表卡片不展示署名，且不会公开池成员身份或跳转到用户主页。

API TypeScript 类型、OpenAPI 模型、服务端 DTO 映射、小程序请求类型与契约文档同步删除 `curatedByName`。后台管理用户查询额外返回池成员标识；该标识不进入匿名或用户侧 API。

## 验证与发布

1. 迁移前后运行只读计数和外键引用检查；确认旧空 owner 灵感条目与其依赖均被清理，且最终菜谱表零空 owner。
2. 覆盖发布、改编、审核收录、后台创建、导入发布五条写入链路：均断言 owner、昵称快照以及用户改名后快照不变。
3. 覆盖公共池：恰好 100 个 active 成员才可选择；少于/多于/含禁用成员均拒绝发布；后台用户列表可显示成员状态，小程序接口不能看到它。
4. 覆盖灵感详情：仅返回 `owner`，不含 `curatedByName`；空昵称隐藏署名；“我的”和灵感详情均读取冻结快照。
5. 运行 API 单元/集成测试、Prisma 校验与迁移检查、API type-check、客户端 type-check 和小程序生产构建；完成后台浏览器与小程序真机验收。

## 明确不做

- 不公开用户池名单、成员资格或用户主页入口。
- 不把公共内容池用于真实饭局参与、计划操作、权限或任何用户身份推断。
- 不提供 owner 转移、昵称快照回填或 `curatedByName` 兼容返回。
- 不修改现有菜谱列表布局、滚动行为或历史记录产品能力；本次仅清理已确认的旧无 owner 灵感菜谱及其依赖引用。
