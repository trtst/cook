# 灵感添加到私房菜并选择个人分类

## 目标

“添加到私房菜”与“收藏灵感”是同一个用户操作。用户从灵感详情添加菜谱时选择一个个人分类；添加结果继续引用灵感固定版本，不创建个人菜谱副本，并保留原作者署名。

## 当前差距

详情页最近将原有的分类选择面板替换为无分类的收藏面板。现有 `RecipeCollection` 已承接添加到私房菜的只读固定版本关系，但没有个人分类字段；添加请求只传 `sourceRecipeId + sourceVersionId`，列表也没有个人分类筛选。因此仅恢复原 Vue 面板不能保存和使用分类。

## 用户流程

1. 用户在灵感详情点击“添加到私房菜”。
2. 上滑面板加载当前用户个人分类，并提供现有的新建分类入口。
3. 用户选择一个分类并确认。
4. 服务端校验分类属于当前用户，并在同一收藏关系上保存分类、来源菜谱和固定正文版本。
5. 添加成功后详情显示已添加；私房菜的“收藏的灵感”列表可按个人分类筛选，并展示来源署名。
6. 移除操作仍删除这条固定版本关系；不改变来源菜谱。

## 数据与接口

- `RecipeCollection` 增加必填的 `categoryId` 及个人分类关系。
- 新的添加请求要求 `categoryId`。写入时服务端校验分类的 `userId` 与当前用户一致。
- migration 先删除现存 `recipe_collections` 收藏关系（其场景关联随外键级联删除），并将由这些关系派生的菜谱 `collectCount` 重置为 `0`，再新增必填分类字段和外键。用户确认不保留旧收藏数据、不做分类回填。
- 收藏列表支持可选 `categoryId` 筛选，并返回该关系的 `personalCategory` 摘要；不传分类时仍返回全部新收藏记录。
- 详情的已添加状态继续按当前固定版本匹配；无需新增收藏接口或用户可见的第二种收藏概念。
- 保存、移除、不同版本的唯一关系及 `collectCount` 规则保持不变。

## 客户端行为

- 复用此前 `AddToPrivateSheet` 的个人分类选择、创建分类、加载失败重试和登录处理。
- 使用“添加到私房菜”作为该操作的主文案；已添加状态允许移除。
- “收藏的灵感”列表提供个人分类筛选；默认显示全部。
- 不把灵感条目塞入本人可编辑菜谱集合；不提供新建第二种“收藏”关系。

## 验收

- 用户不能把收藏关系关联到其他用户的分类。
- 选择分类添加灵感后，列表返回相同个人分类，按该分类筛选能找到它。
- 重复添加同一固定版本不重复增加关系或 `collectCount`。
- 移除收藏后关系和分类关联一并删除，来源菜谱与正文版本不变。
- 无个人分类时，用户可在面板创建分类并自动选中后继续添加。

## 本轮不做

- 创建个人菜谱副本或改写菜谱归属。
- 保留或迁移现存的旧收藏关系。
- 在后台增加分类治理入口。
- 增加另一种用户可见的收藏/合集功能。
