# 购物清单与冰箱低维护 V1 产品基线

## 状态

2026-09-24 已由用户确认，作为购物清单与冰箱 V1 产品基线。本文取代此前关于精确库存、库存差额、库存预占、采购入库和做饭自动扣减的 V1 设计；旧文档只保留历史记录，不作为当前实现或兼容入口。

本文只冻结业务流程、页面行为和产品边界。API、数据库、迁移和兼容策略仍须按 docs/api-database-rules.md 单独评审。

## 一、核心职责

| 对象 | V1 职责 |
| --- | --- |
| 菜谱、计划、饭局 | 告诉用户本顿需要准备什么、买多少 |
| 购物清单 | 展示完整需求，只维护待买和已买 |
| 冰箱页面 | 展示系统根据行为留下的近期痕迹，不要求维护 |

## 二、确认菜单与采购

确认计划或饭局菜单时，展示：

> 本顿需要准备 X 样食材

同时提供 去采购 按钮。

规则：

1. 采购提示来自固定菜谱版本、当前人数和菜谱需求。
2. 不读取或扣除冰箱库存，不判断真实缺口。
3. 不点击 去采购，不写入购物清单或冰箱。
4. 点击后生成完整需求清单，而不是库存差额清单。
5. 相同食材且单位相同的菜谱用量可以合并展示；无法可靠换算时分开。
6. 适量保留为文字，不转换为精确数量。

## 三、购物清单

购物清单每行展示食材、需求量和来源，状态为：

- 待买
- 已买
- 不买了

用户只通过勾选标记 已买，支持 全部买到。不得要求输入实际数量、价格、入库数量或到期时间；用库存、库存预占和入库确认不进入 V1 主路径。

勾选 已买 后立即留下购买痕迹，冰箱可显示 最近买过，可能有。它不是库存入库，不参与数量计算。取消勾选只撤销本次购买痕迹，不影响更早记录。

## 四、做饭完成

用户点击 这顿做完了 后，可以留下 用过，余量未知 的痕迹。

该动作不扣减库存、不计算剩余数量、不执行批次扣减、不提供库存撤销，也不阻塞做饭完成。

做饭前不再逐项确认库存，不保存 有/没有 的库存决策。

## 五、冰箱页面与时间衰减

冰箱页面只展示近期仍有参考价值的痕迹。用户可以选：

- 还有
- 用完
- 手动添加食材
- 删除痕迹

这些操作不接受数量、单位、批次或到期时间。

展示有效期是信息可信度衰减，不是食品安全保质期：

| 食材范围 | 展示时间 |
| --- | --- |
| 蔬菜、水果、鲜肉、鲜鱼、豆制品、鲜奶等易腐食材 | 7 天 |
| 其他食材 | 15 天 |
| 无法判断分类 | 15 天 |

超过时间后，从默认冰箱页面隐藏，不显示为没有或过期，也不参与采购判断。用户再次勾选 已买 或手动标记 还有 后重新开始对应周期；标记 用完 时立即隐藏。

## 六、V1 不做

1. 做饭前库存确认及其持久化。
2. UNKNOWN、NEED_CONFIRM、CONFIRM_ENOUGH 等精确库存状态主路径。
3. 库存差额、库存预占、用库存和 FEFO。
4. 精确数量、单位换算、批次、到期时间和自动扣减。
5. 采购完成入库确认、扣减撤销和库存流水。
6. 因库存未知而阻塞菜单确认、购物或做饭。
7. 共享冰箱和通用库存管理中心。

现有精确库存、批次和预占代码、字段和入口不纳入新版实现；涉及历史数据清理或前向 migration 时，必须单独说明风险和部署顺序。

## 七、验收标准

1. 确认菜单时看到需要准备数量和 去采购，但不自动写入。
2. 去采购生成完整需求清单，不做库存差额。
3. 购物只需勾选已买。
4. 已买产生购买痕迹，做饭完成产生使用痕迹，两者都不参与库存计算。
5. 易腐食材 7 天、其他食材 15 天后从默认冰箱页隐藏。
6. 不打开或不修正冰箱，不影响菜谱、计划、饭局和购物。
