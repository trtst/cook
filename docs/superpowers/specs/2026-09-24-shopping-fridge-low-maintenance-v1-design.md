# 购物清单与食材低维护 V1

## 状态

2026-09-24 V1 产品基线已定稿。本文是本功能唯一产品文档；API、数据库和页面实现仍按项目规则单独评审。

## 一、核心流程

### 1. 确认菜单

- 展示本顿需要准备的食材和菜谱用量。
- 可提示“之前记录有，数量请自行判断”，但不计算真实缺口。
- 饭局主家确认菜单时使用简短确认弹窗，提示确认后菜单将固定且不能再调整；纯计划保持单次点击确认。
- 离开页面不产生写入。点击“去采购”后生成完整购物需求，直接进入购物清单；有进行中的清单时追加，没有时自动创建，不弹确认层。
- 计划页、饭局页和确认菜单页均不提供手动添加食材；手动添加只在购物清单中进行。

### 2. 购物清单

- 菜谱食材以名称为主；精确用量以次要弱提示显示“本次约需 X”，模糊用量显示“适量”。用量仅供参考，不要求用户核对或按量购买，不代表库存余量或是否买够；没有用量时不补造数量。
- 清单详情不显示食材图片；食材项两行展示：首行左侧为名称和分类、右侧为状态，次行左侧为本次约需量、右侧为来源入口。来源可展开并显示项数，展开时下箭头动画转向上。购买状态使用主题化勾选框；可编辑清单在页面底部常显“添加食材”，右上角设置上滑 Sheet 提供“作废清单”，不提供改名。
- 手动食材：显示食材和“按需购买”，不输入数量。
- “近期要准备”页只汇总待处理饭局的菜单需求，不读取冰箱余量或计算缺口；用户自行决定是否加入清单。
- `meal-footer-panel` 保持现有布局：分享/发起饭局入口 + 主按钮，不新增操作按钮。`meal-shopping-panel` 保留现有“去采购 / 查看清单”入口，并新增“已备齐”快捷入口。
- 点击“已备齐”表示当前这顿饭的全部食材已准备好，直接跳过购物清单；只更新当前餐次/饭局准备状态，不写入长期食材状态，也不记录数量。逐项购买仍由清单“已买”勾选即时生效并同步饭局进度；“家里有，不用买”仅对对应饭局的食材来源生效。
- 食材准备完成后主按钮显示“开始做饭”；饭局开始后提供快捷“结束饭局”。
- `meal-shopping-preview__row` 沿用菜单列表布局：左侧食材名称、右侧数量提示，不显示来源菜谱名称。
- 只通过勾选维护“已买”；勾选后食材状态更新为“有”并记录购买时间，不要求入库数量、单位或到期时间。
- 饭局关联的清单食材可标记“已买”或“家里有，不用买”。后者只完成当前饭局的该项准备确认，不写入长期食材状态；同一食材关联多个饭局时，按饭局分别确认。清单中没有饭局来源的手动食材不影响饭局准备进度。
- 饭局进度只汇总来自该饭局的食材来源；关联食材均已买或确认家里有后，显示“食材已备齐”，主入口转为“开始做饭”。饭局开始后提供快捷“结束饭局”入口。该状态依据用户确认，不代表系统计算了数量或库存充足度。
- 状态提示统一为：“有”显示“可能还有”，“没有”显示“已标记没有”，“未确认”显示“没有近期记录”；最近一次勾选“已买”后的 3 天内显示“最近买过”。不显示准确余量。
- 用户自行决定是否继续购买，暂时不买不写入食材状态。

### 3. 添加食材（已确认交互）

购物清单点击“添加食材”后打开上滑 Sheet：

1. 复用菜谱编辑中的食材搜索和选择能力。
2. 支持多选，底部按钮显示“添加 N 项”。
3. 确认后关闭 Sheet，新增项进入待买列表，数量显示“按需购买”。
4. 已在清单中的食材不重复添加，并提示“已在清单中”。
5. 不显示数量输入、单位输入或库存确认。

手动添加的食材没有菜谱来源，不记录精确余量；勾选已买后按上面的规则更新状态并显示购买痕迹。

### 4. 食材页面

用户只维护“有 / 没有”。数量、单位、批次和到期时间不进入 V1。

- 首次打开时列表为空，不要求初始化；在食材页手动添加时默认标记为“有”，并记录当前时间。
- “未确认”表示没有近期确认或记录已超过展示窗口，不等于“没有”。用户确认状态或勾选已买后开始对应展示周期。
- 蔬菜、水果等易腐食材：7 天后降为“未确认”。
- 其他或无法判断的食材：15 天后降为“未确认”。
- 距最近一次状态更新时间超过 30 天后，移入默认收起的“很久没记录（X 项）”折叠区；展开后仍可标记“有 / 没有”，不设数量上限。
- 不保留完整操作历史：每种食材最多保留最新一条“有 / 没有”状态、最近购买和最近用过痕迹；新痕迹写入后删除同食材更早的记录。未发生新写入时不做定时清理。

购买和做饭完成都不扣减数量，也不会自动把食材标记为“没有”；勾选已买时按购物清单规则将其更新为“有”。

### 5. 饭局完成后的入口

实际饭局或餐次完成后，在页面底部提供可跳过的更新入口；不弹窗，也不按食材项数或距上次更新时间设置显隐门槛：

> 饭局结束啦，要不要顺手看看食材还有没有？

按钮：

- “更新食材”：展示本顿所有菜谱涉及的食材，每项可标记“有 / 没有”。底部“全部确认有”为主按钮，“全部跳过”为次按钮；跳过不改变状态，只有用户明确选择的结果才更新食材页，不改购物清单、不参与计算。
- “分享回忆”：进入回忆流程，不要求先更新食材。

计划单纯到期不等于饭局完成，不自动显示“分享回忆”，也不触发库存写入。

饭局/计划详情正文底部提供对应的“取消饭局 / 取消计划”入口；饭局按预定开席时刻判断，计划按本餐预定时间判断，无具体时刻时在计划日期结束后隐藏。饭局取消前进行二次确认，取消后状态与正常完成区分，不进入完成后的食材更新和分享回忆流程。正常结束饭局才可更新食材或分享回忆。

## 二、V1 不做

- 精确库存、数量计算、单位换算、批次和 FEFO。
- 库存差额、预占、用库存、自动扣减和采购入库确认。
- 做饭前逐项库存确认及其持久化。
- 共享冰箱和通用库存管理中心。

## 三、验收标准

1. 去采购前不写入清单，去采购后生成完整需求。
2. 菜谱项以食材名称为主，有明确菜谱用量时仅弱提示“本次约需 X”；手动项显示“按需购买”，不提供数量输入或用量显示开关。
3. 添加食材不要求输入数量，重复食材不重复添加。
4. 购物只需勾选“已买”，提示库存但不计算余量。
5. 食材页只维护“有 / 没有”，7/15 天后不再把旧记录展示为当前有。
6. 实际饭局完成后可更新食材或分享回忆，二者互不阻塞。
7. 饭局食材可按“已买 / 家里有，不用买”完成准备确认；全项处理后显示“食材已备齐”和“开始做饭”，饭局开始后可快捷结束；“家里有”不修改长期食材状态。
8. 饭局详情保留现有 footer 布局和采购入口，新增“已备齐”一键跳过清单；准备预览只显示食材与数量。取消入口位于详情内容末尾，到预定用餐时间后隐藏；取消饭局需二次确认，且不触发正常完成后的食材更新或回忆分享。
