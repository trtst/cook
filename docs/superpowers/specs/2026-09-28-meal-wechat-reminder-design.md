# 饭局与计划微信提醒设计

## 用户目标

在饭局或计划详情页为当前用户开启一条微信订阅提醒；重新进入详情时可以看到这条提醒是否已预约。微信提醒提前两小时触发，让用户有准备时间。

## 已确认规则

- 底部固定保留「微信提醒」入口和当前主操作。
- 当前动态快捷操作（例如「发起饭局」「分享邀请」）和「取消饭局 / 取消计划」放入参考计划列表页的右下角浮动管理菜单。
- 点击「微信提醒」时由小程序请求当前微信订阅模板授权。授权结果按当前用户和当前饭局/计划记录；本提醒只发给主动授权的当前用户，不代替其他饭局成员授权。
- 再次进入详情，从服务端读取提醒状态。客户端展示「未预约」「已预约」「已发送」等状态；微信的一次性订阅授权不表述为长期微信开关。
- 饭局按实际 `scheduledAt` 提前两小时触发。模板的预约时间展示具体开席时间；备注保留开席时间与提前准备信息，例如「18:30开饭，约2小时后开始，可准备。」微信 `thing` 字段最多 20 字，发送值必须满足该限制。
- 纯计划按服务端对应餐次参考时点提前两小时触发，但不将该推算时点当作准确开饭时间展示。`预约时间`字段只放计划日期；备注按计划日期和餐次生成，例如「今天有晚餐计划，可提前准备。」
- 饭局改时间时，未发送提醒随开席时间重排；饭局或计划取消后删除未发送提醒和相应待投递工作，不保留取消内容。
- 若用户授权时距离触发时点不足两小时，本次提醒不进入待投递状态，并明确告知无法为本次安排两小时提前提醒。

## 历史实现边界

已移除的食材临期链路支持用户点击后立即发送订阅消息，不包含未来定时投递、饭局/计划维度的授权状态或详情状态查询。其临期模板字段与本功能不同，不得复用。当前 `apps/worker` 明确未启用；本功能需要新增仅服务饭局提醒的定时投递消费能力，不启用其他通用后台任务。

## 推荐实现结构

1. 在饭局/计划业务 API 中提供当前用户的提醒状态读取和预约写入。客户端只有在微信对本模板返回 `accept` 后才写入预约；拒绝、受限或不支持时不伪造已预约状态。
2. 用用户拥有的饭局提醒记录保存授权时间、目标饭局或计划、待触发时间和投递状态。数据库唯一约束保证同一用户对同一餐次最多一个有效提醒；取消或完成后清理未发送记录。
3. 在同一数据库事务中写入提醒预约和 Outbox 工作项。仅启用专用 worker 消费饭局提醒，到期后再次校验目标仍有效、时间未改动且当前用户仍有权读取目标，再调用微信发送。
4. Worker 使用现有 Outbox 状态与 `nextRunAt` 语义，实现有界批次、跨实例领取锁、失败分类和有限重试；消息发送成功后更新提醒状态。日志只记录资源 ID、结果码和必要时间，不记录 openid、token 或私有备注。
5. 现有餐次/推荐偏好开关继续保持独立偏好语义。本功能不把通用提醒设置开关改造成微信发送开关；提醒设置页文案需说明饭局微信提醒应在详情页单独预约，避免继续显示“微信通知尚未接入”。

## 状态与页面行为

| 当前状态 | 详情页状态 | 用户操作 |
| --- | --- | --- |
| 没有有效预约 | 未预约 | 点击固定「微信提醒」并请求微信授权 |
| 已获本次授权、等待发送 | 已预约 | 显示目标和触发时间；已取消或失效的目标不再保留 |
| 消息发送成功 | 已发送 | 只展示已发送状态，不自动再次发送 |
| 授权不足两小时或时点已过 | 未预约并显示原因 | 不发送迟到提醒；用户可为下一次重新预约 |
| 用户拒绝、微信限制或模板配置不可用 | 未预约并显示失败原因 | 保留详情页状态，允许稍后重试 |

饭局和计划各自的取消权限继续由现有业务服务校验；客户端隐藏管理菜单动作不代替服务端校验。饭局取消沿用已确认的删除规则，并在同一业务转换中清理待发提醒。

## 模板与部署前置条件

- 当前确认的微信订阅消息模板：template ID `LJwjRWjXD6Hod0iJnswKX91ZTyq3bqQM6HtDb1FiiDo`，模板编号 `2233`，标题「预约到期提醒」，类目「办公」；字段 `date2.DATA` 为预约时间，`thing3.DATA` 为备注。
- template ID 是微信授权 API 必需的公开模板标识，不是密钥：客户端将其用于 `requestSubscribeMessage`，服务端用相同 ID 发送模板消息。它不作为通知正文展示，不得与 `WECHAT_APP_SECRET` 混淆；旧食材临期 template ID 不适用。
- 客户端和服务端必须使用同一模板 ID；服务端从 API 环境配置读取。发送的 `date2` 值符合该模板的日期格式要求；计划只传计划日期，不传服务端内部参考时点。
- 使用现有 `WECHAT_APP_ID` 和 `WECHAT_APP_SECRET` 获取服务端 access token。真实发送还需在微信开发者工具或真机上完成授权与模板发送验收。

## 验收边界

- 详情重进后状态由 API 返回，不依赖客户端本地缓存。
- 饭局与计划的预约仅通知主动授权的当前用户；不能越权预约其他用户的计划。
- 微信拒绝、受限、不支持、模板配置缺失、时间修改、取消、重复请求、重复 worker 领取和外部发送失败均有可解释的结果。
- API/worker 代码检查不能替代微信端模板授权和真实投递验收；没有真实模板 ID 与微信端结果前，不声明端到端发送完成。
- 投递按至少一次处理：发送结果不确定时继续有限重试，因此极少数情况下可能重复；单条领取和 15 分钟过期恢复用于降低并发重领概率，不能提供严格 exactly-once 保证。
- 分享预览只有 `eventId`、没有计划项时，饭局详情仍显示微信提醒入口；计划专属操作不因此显示。

## 实施范围外

- 重新接入食材临期提醒。
- 通用通知中心消息、全局微信提醒开关或所有业务的通用定时任务。
- 给未主动授权的饭局参与人发送提醒。
- 将微信一次性订阅授权描述为可长期查询的微信开关。
