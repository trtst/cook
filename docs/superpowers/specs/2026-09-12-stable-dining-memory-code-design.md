# 固定饭局回忆码设计

## 已确认目标

每个饭局只拥有一个稳定的小程序码。饭局发起人首次从饭局详情打开活动回忆卡时申请并保存该码；后续重新导出海报、修改本地标题、更新公开文案或成员展示时，都复用同一张码。二维码不能暴露饭局 ID，也不能直接进入需要登录和成员权限的饭局/计划详情。

## 入口与数据流

小程序码固定打开 `pages_share/memory/index`，其 `scene` 为由饭局 ID 和服务端密钥签名的饭局回忆标识。公开预览接口校验签名后，按饭局查询最新一份回忆快照并返回现有白名单字段。公开回忆页保持为隐私安全的落地页；饭局邀请继续使用 `pages_share/preview/index` 和独立邀请签名，不受此改动影响。

首次打开活动回忆卡时，客户端调用既有创建快照接口；服务端从稳定标识生成微信小程序码并把对象键记录在饭局上。创建后续快照时直接读取该对象键，不再请求微信生成或重复存储二维码。每份快照仍保存当时的菜单、成员、封面和文案；公开稳定入口始终返回该饭局的最新快照。

## 生命周期、权限与失败语义

- 稳定码 owner 是饭局；只有饭局发起人且饭局已到开饭时间或已完成，才能首次创建回忆快照。
- 稳定码不保存明文标识；签名可由饭局 ID 重建，数据库仅保存二维码对象键。
- 饭局取消时不得创建新回忆卡；现有公开预览继续遵循当前快照读取规则，未新增撤销功能。
- 公开读取仅校验签名并返回最新快照既有的白名单字段，不读取饭局私有详情。
- 已存在但缺少稳定二维码对象键的历史饭局，在下一次创建回忆卡时生成一次并补齐该键。

## 前端行为

编辑回忆卡标题只重新导出 Canvas 图片，不创建新的服务端快照。修改公开文案或成员可见性时会创建一份新的快照，但后续图片继续使用饭局固定二维码。重新进入编辑页后，页面加载会创建最新快照；二维码不会重复请求微信。

## 非目标

- 不将二维码改为饭局/计划详情的私有直达链接。
- 不改变饭局邀请链接、邀请接受或其失效规则。
- 不新增二维码撤销、刷新或多码管理入口。
