# 配置、会员与个人空间规则

## 文档定位

本文是个人 Free、Plus、Pro、Ultra 权益、个人空间计量、图片、派生做法、回收站、降级和配置中心的当前权威文档。饭搭子协作规则见 `dining-group.md`，菜谱数据规则见 `recipe.md`，食材与单位规则见 `ingredient.md`。

只销售个人会员。饭搭子是免费协作关系，不单独售卖饭搭子空间、共享会员或成员席位。

## 一、配置边界

服务端是权益和额度的唯一权威。客户端只展示服务端解析结果，不自行推导套餐、额度、超额状态或可操作结论。

配置中心可以管理：

| 类型 | 用途 |
| --- | --- |
| `GLOBAL` | 全局业务默认值和常用限制 |
| `ENTITLEMENT` | 四档个人套餐的额度和功能 |
| `USER` | 用户提醒和个人偏好 |
| `INSTANCE` | 邀请、饭局等创建时需要固化的策略值 |
| `SAFETY` | 代码中的安全硬上限 |

数据所有权、成员身份、权限边界、状态机、过敏安全、支付真实性和合规限制不能仅靠配置决定。

后台配置修改必须校验类型和安全上限，记录策略版本、修改人、修改原因和生效时间。降低额度不直接删除已有核心数据。

“可加入饭搭子数”包含自己创建的饭搭子。免费用户创建自己的饭搭子后，不能再加入其他饭搭子。

`Ultra` 当前确切硬上限为 `350` 道菜谱和 `2 GB`，不使用“+”。未来扩容包需要独立产品和支付规则，不提前混入当前套餐。

## 三、图片规则

图片质量数值是服务端编码质量策略，不代表原图百分比承诺。所有档位的上传都必须：

1. 修正方向。
2. 删除 EXIF、位置和设备信息。
3. 校验真实文件类型、尺寸、体积和像素总数。
4. 防止压缩炸弹、伪造扩展名和恶意文件。
5. 在服务端重新编码，不直接信任客户端压缩结果。
6. 经过必要的内容安全检查后再对其他用户可见。

最大宽高、单图输出大小和原始上传上限由后续图片契约冻结。客户端不得仅根据质量值自行决定上传参数。

背景图、饭搭子主页主图与后期头像装饰上传计入个人空间，并遵守相同的压缩、隐私清理和内容安全规则。

## 四、菜谱数量

以下都计入个人菜谱数量：

1. 手动创建的菜谱。
2. 导入后形成的个人菜谱入口。
3. 个人独立菜谱。
4. 派生做法。
5. 收藏到合集的只读固定版本。
6. 新建菜谱的草稿。
7. 回收站中尚未永久删除的菜谱。

同一道收藏加入多个个人场景仍只计一个名额。收藏升级为“我的”不重复计数。已有菜谱的编辑草稿不额外增加菜谱数量。归档不是删除，仍计入数量；只有取消只读收藏或永久删除相应个人菜谱才释放名额。

数量超额时不删除已有菜谱。禁止新建草稿、收藏、导入和另存派生做法；已有菜谱仍可查看，是否允许普通编辑取决于个人空间是否同时超额。

## 五、个人逻辑空间

个人总逻辑空间包括：

```text
个人已用空间
= 菜谱基础结构化数据
+ 个人覆盖修改和管理数据
+ 个人独立菜谱结构化数据
+ 收藏固定版本的结构化数据和个人场景数据
+ 新建草稿和编辑草稿新增的数据
+ 个人新增或替换的菜谱图片
+ 冰箱、计划、饭局和购物清单数据
+ 被计划、饭局或分享固定引用的必要技术版本
+ 回收站数据
+ 首页和我的页背景图
+ 饭搭子主页主图
+ 后期头像装饰资源
```

导入或收藏菜谱的基础版本可以在物理层复用，但每个持有人的逻辑空间都计算该基础结构化数据。复用的来源图片不重复计入个人空间；个人新增、替换或加工后的图片按服务端最终文件大小计入。

结构化数据按标准化 UTF-8 内容和固定记录开销计量，每条记录至少按 1 KB 向上取整。图片按服务端最终保存的压缩文件大小计量。

不计入个人空间：

1. 仅查看、尚未导入的其他用户菜谱。
2. 饭搭子成员关系和饭局参与关系。
3. 系统公共图片和仍在复用的来源图片。
4. 通知、审计日志、会员配置和系统缓存。
5. CDN 缓存、缩略图和临时上传文件。
6. 口味、过敏和严格忌口资料。

逻辑计量必须支持增量更新和全量重算。计量账本不能成为唯一事实；发现漂移时以业务数据重算结果修正。

## 六、派生做法

“另存为新做法”是主动创建第二道个人菜谱，不等同于普通编辑。

1. 只有根菜谱可以创建派生做法。
2. 派生做法不能再次派生。
3. 每个派生做法独立计入菜谱数量和个人空间。
4. 回收站中的派生做法继续占用派生名额。
5. 永久删除后释放名额。
6. 会员到期不删除已有派生做法，但不能继续超额创建。

具体上限按当前个人套餐解析，不按饭搭子或成员叠加。

## 七、回收站与删除

| 套餐 | 删除行为 |
| --- | --- |
| 免费 | 二次确认后永久删除 |
| Plus | 进入回收站，保留 3 天 |
| Pro | 进入回收站，保留 5 天 |
| Ultra | 进入回收站，保留 7 天 |

回收站中的数据仍计入菜谱数量和个人空间。用户可以提前永久删除。被饭局、计划或其他用户菜谱固定引用的基础技术版本，在引用释放前不能物理删除，但不会恢复为原用户的可见菜谱。

## 八、会员降级

会员到期或配置降低后立即按新套餐解析：

1. 已有高清图片不主动降质，新上传按当前套餐处理。
2. 已有派生做法不删除，超额时禁止继续创建。
3. 菜谱数量超额时禁止新建草稿、收藏、导入和派生。
4. 空间超额时进入个人空间只读，只允许查看、永久清理、导出、续费和用户安全操作。
5. 饭搭子人数超额按 `dining-group.md` 进入超额受限，只允许查看和减少关系。

个人空间只读不得阻止永久删除、导出或修改过敏等安全资料。清理到额度以内后自动恢复当前套餐允许的写入能力。

## 九、饭搭子额度性质

饭搭子关系本身不收费，个人会员只决定本人可以扩展的协作规模：

1. 主理人的套餐决定自己饭搭子的可邀请人数。
2. 接受人的套餐决定本人可加入饭搭子数。
3. 两个用户的额度不能相加。
4. 邀请和接受都必须由服务端在事务中重新校验。
5. 降级超额不自动踢人，但冻结增加和编辑类饭搭子操作，直到恢复到当前额度。

## 十、个性化权益

主题皮肤按套餐开放预置资源。背景图权限只有“有/无”，不按上传数量分档。

首页背景图和我的页背景图属于用户个人展示，不改变其他用户的推荐、投票、权限或安全判断。未来头像装饰沿用基础、高级、全部三档资源范围，具体资源清单由配置管理。

## 十一、支付与续费边界

会员开通、升级和续费只接受直接支付。饭票、积分或其他非现金资产不得购买、抵扣或参与混合会员支付。

四档价格、周期、升级补差和退款规则尚未在本轮冻结。在支付契约确认前，不实现销售入口、订单 DTO 或自动续费。会员页只能展示已经真实实现并可验证的权益。

## 十二、兑换码与体验规则

当前这轮小程序内只实现会员兑换码核销入口，不实现站内下单、订单 DTO、支付回调或自动续费。正式购买发生在小程序外部，用户在小程序内登录后输入兑换码到账。

### 12.1 正式会员兑换码

1. 正式会员兑换码只发放个人会员，不发放饭搭子级权益。
2. 当前固定 SKU 目录只保留 `PLUS_30D`、`PRO_30D`、`PRO_TRIAL_1D`、`PRO_TRIAL_3D`、`PRO_TRIAL_7D` 五项；后台只能基于这五项创建批次和发码。
3. 只有 SKU 与批次都处于允许核销状态，且在批次兑换时间窗内，兑换才可成功。
4. 同档会员兑换按剩余有效期顺延；`PLUS` 兑换 `PRO` 按升档顺延；`PRO` 兑换 `PLUS` 首版直接拒绝。
5. 兑换成功后的最终事实仍只写用户级有效权益，不再建立第二套客户端会员事实。

### 12.2 体验码

1. 体验码与正式会员码分批次管理，但统一走兑换码核销入口。
2. 当前体验档位固定为 `PRO`，体验天数只允许 `1 / 3 / 7` 三档。
3. 体验码不允许自由输入任意天数，后台只提供 `1 / 3 / 7` 选项。
4. 同一用户历史体验累计天数不得超过 `7` 天；超过后必须改发正式 `Plus / Pro` 会员。
5. 已有正式 `PLUS / PRO / ULTRA` 有效会员的用户不得再兑换体验码。
6. 体验批次可以分批生成、分批停用；某一批泄露时，只停该批，不影响其他批次。

### 12.3 核销安全口径

1. 兑换码必须高熵随机生成，数据库只保存 `codeHash` 和掩码，不保存明文码。
2. 单码只能成功一次；并发核销必须锁定单码事实并在事务内完成到账、标记已用和审计。
3. 核销失败统一返回“兑换码无效或不可用”，不向用户暴露“已使用 / 已停用 / 未上架 / 超过体验上限”等内部状态。
4. 核销接口必须带幂等键，并按用户、设备和 IP 做限流与冷却。
5. 审计、日志和后台列表不得记录或展示完整明文兑换码。
6. 后台生成后的明文兑换码只在当次导出结果中返回一次；后续查询、审计和列表都只允许使用掩码。
7. 单次后台批量生码上限固定为 `1000`，超过时必须分批生成，降低误操作和导出泄露面。

## 十三、广告展示规则

广告展示与会员档位相关，但广告本身不是会员事实表。页面广告位必须按服务端或配置解析结果决定是否展示，不能由各页面自行散写判断。

1. `Free` 默认展示普通被动广告位，也可以主动观看激励广告换额外次数。
2. `Plus` 只减少高打扰被动广告位，不承诺完全无广告；激励广告仍可主动触发。
3. `Pro` 与 `Ultra` 默认不展示被动广告位，但仍可在用户主动领取额外次数时展示激励广告。
4. 体验态 `Pro` 按 `Pro` 的广告策略执行，否则体验感与正式权益不一致。
5. 做饭助手、识图等次数型能力后续单独记账；广告奖励优先换次数或体验资格，不直接替代正式会员销售规则。

## 十四、安全与性能

1. 权益解析结果可以短时缓存，但写操作必须使用当前服务端事实重新校验。
2. 成员数、加入数、菜谱数和空间使用量必须有合适索引，禁止每次加载页面全表扫描。
3. 额度写入必须锁定最小必要主记录，防止并发突破且避免扩大锁范围。
4. 清理任务必须幂等、分批、可重试，并记录审计。
5. 任何额度或配置错误都不能自动删除用户核心数据。
