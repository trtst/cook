# 食材与计量单位规则

## 文档定位

本文是系统食材库、个人食材、计量单位、审核入库和菜谱用量表达的当前产品权威文档。本文只确认产品行为和数据语义，不冻结 API、DTO、表、索引、换算精度或迁移。

## 一、统一食材库

系统只建立一套统一食材库，不分别建立蔬菜库、佐料库或调味品库。食材通过系统分类组织。

首版系统分类：

1. 蔬果菌菇。
2. 肉禽蛋。
3. 水产海鲜。
4. 豆乳制品。
5. 米面杂粮。
6. 调味料。
7. 干货腌制。
8. 酒水饮料。

系统内部额外保留一个隐藏兜底分类：`待归类`。该分类不对前台和后台常规录入开放，只用于历史脏数据、导入异常和临时过渡治理。

“原料、配料、调料”不是食材自身属性。如产品需要区分，应由具体菜谱中的食材关系表达，不能把同一食材复制成多个系统食材。

分类本身不配置上传图片。个人食材不配置单项图片；系统食材允许由后台在后期补传单张小图，当前终存 `50x50`，用于后续小图展示。这样既能控制图片治理成本，也避免把图片变成个人创建食材时的必填身份信息。

系统食材治理补充规则：

1. 后台支持把系统食材设为 `启用中 / 已下架`，不做物理删除。
2. 已下架系统食材不再出现在新建和编辑菜谱的食材选择器里。
3. 已发布菜谱中的食材名称快照不因系统食材下架或重新上架被回写。
4. 已下架系统食材重新上架后继续使用原食材身份，但恢复时按当前分类末尾重新参与系统排序。
5. 前台可对系统食材提交纠错，当前只收口 `名字 / 分类 / 备注`，用于描述名称、分类或图片展示不符等问题。
6. 系统食材纠错进入后台人工审核；审核采纳后直接更新对应系统食材，驳回只记录审核备注，不生成新的系统食材。

## 二、食材选择器

食材选择器包含：

1. 搜索框。
2. `全部食材 / 我的` 来源切换。
3. 左侧系统分类。
4. 右侧三列文字宫格。

搜索同时覆盖系统食材和本人食材，但结果必须保留来源识别。选择器不因分类过多变成长页面列表。

选择器补充规则：

1. 默认进入 `全部食材`，显示系统食材和本人仍可用的个人食材；排序固定为系统食材在前、个人食材在后。
2. `我的` 只显示本人仍可直接使用的个人食材；已通过并转成系统食材后，不再出现在 `我的`。
3. 个人食材条目提供 `编辑` 和 `推荐` 明确操作；推荐确认弹窗标题保持 `推荐入系统库`；审核状态不放进选择器弹层。
4. 搜索无结果时允许直接进入“创建个人食材”，创建成功后立即回到当前菜谱选择流。

## 三、新建我的食材

用户找不到需要的食材时，可以新建个人食材。

个人食材必填：

1. 名称。
2. 默认单位。
3. 一个系统分类。

新建后立即在本人食材库可用，不需要等待审核。个人食材不会因加入饭搭子而共享给其他成员。

用户通过明确操作推荐入系统库，不能在创建时默认投稿。后台审核结果包括：

1. 新增为系统食材。
2. 合并到已有系统食材。
3. 拒绝。

补充规则：

1. 审核中不允许再编辑该个人食材，但不影响继续用于当前菜谱。
2. 拒绝后恢复可编辑，并允许用户修改名称、分类和默认单位后重新推荐。
3. 后台审核通过时可修改 `名称 + 分类 + 默认单位`。
4. 若系统库已有同名食材，创建个人食材时直接拦截；若推荐时命中启用中的同名系统食材，则直接归并，不再进入待审队列；若只命中已下架同名系统食材，则继续进入后台审核，由后台决定是否恢复复用。
5. 合并后要把本人草稿和菜谱内容中的食材引用直接切到系统食材，不保留一条继续对外可见的重复个人食材。
6. 推荐记录统一在“我的 -> 我的推荐”查看，不放进通知中心。

## 四、计量单位

系统单位按语义区分重量、容量、数量、容器和包装等类型。只有产品确认存在稳定关系的单位才允许换算，不能因为名称相似就自动换算。

用户可以新建个人单位并立即使用：

1. 相同个人单位的精确数量可以相加。
2. 审核或换算关系确认前，不允许个人单位与其他单位跨单位换算。
3. 个人单位可通过明确操作推荐入系统库，审核不影响本人继续使用。
4. 单位列表默认系统单位在前、个人单位在后；系统单位优先承载常用单位，个人单位只补系统库暂时没有的内容。

`适量 / 少许 / 按需` 是模糊用量，不是计量单位，不参与数学换算。

## 五、菜谱和购物换算

1. 菜谱食材用量可以是精确数量加单位，也可以是模糊用量。
2. 基准人数变化只换算精确数量。
3. 多道菜进入计划、饭局或购物清单时，只合并相同食材且单位相同，或存在已确认换算关系的精确数量。
4. 模糊用量保持逐项提示，不自动求和为虚假的精确值。
5. 任何自动换算都必须保留用户可理解的原始用量事实。

## 六、初始数据与后续边界

首版建议由平台人工整理 `200～300` 个高频食材及常用系统单位，优先覆盖真实菜谱录入和购物合并需求。

以下内容本轮不冻结：

1. 完整初始食材清单。
2. 单位换算精度和舍入规则。
3. 名称、别名和同义词的唯一性范围。
4. 个人单位推荐入系统库的完整审核与换算链路。
5. API、DTO、索引和后台后续批量治理能力。

进入实现前必须依据 `api-database-rules.md` 单独完成契约、约束、成本和迁移评审。
