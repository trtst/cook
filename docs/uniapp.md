# uni-app 小程序工程规则

## 目标

本文只记录 uni-app + Vue 3 + TypeScript 面向微信小程序时的工程规则。

这些规则不承载具体产品口径，重点约束页面、分包、请求、状态、滚动、分享、样式兼容和验证方式。

## 分包规则

1. 主包只放启动必需页、tabbar 页、全局壳层、请求层、基础 store 和真正跨域复用的基础组件。
2. 详情页、编辑页、列表页、分享落地页、资源较重页面默认优先放分包。
3. tabbar 页面必须在主包；tabbar 首屏强依赖的组件要谨慎放入根公共目录，避免主包被动变大。
4. 分包私有组件放在当前分包内，例如 `pages/xxx_sub/components/`。
5. 只服务单个页面或单个分包的组件，不要提前提升到根 `components/`。
6. 分包之间不要互相 import 私有组件、私有 helper 或页面文件。
7. 跨分包真实复用发生后，再考虑提升到根公共组件；提升前先检查它是否会把重依赖拖进主包。
8. `pages.json` 的 `subPackages.root` 必须和真实目录语义一致，路由、白名单、分享路径要同步维护。
9. 分包页面不能假设用户一定先进入首页；扫码、分享、订阅消息都可能冷启动直达分包页。
10. 分包专用图片、富文本、样式和 helper 默认留在分包内，不要放进全局资源目录。

## 路由扁平化

小程序路由默认保持浅层。

1. 页面路径默认只表达 `主包/页面` 或 `分包/页面`。
2. 不把业务模型链写成多层路径，例如饭搭子、菜谱、版本、编辑、状态都不进入同一条路由。
3. 分包 root 按一级产品域命名，例如 `pages_recipe`、`pages_meal`、`pages_pantry`。
4. 分包下页面直接用短页面名，例如 `detail`、`edit`、`poll`、`gap`、`supermarket`。
5. 页面上下文通过 query 传入，页面进入后再调用 API 校验权限和拉取权威数据。
6. 需要兼容旧路径时写 router helper，不新增一套更深的新路径。

推荐：

```text
pages/home/index
pages_recipe/detail
pages_recipe/edit
pages_meal/poll
pages_pantry/gap
pages_share/preview
```

避免：

```text
pages/dining-group/recipe/version/detail
pages/meal/poll/result/confirm
pages/pantry/shopping/list/item/edit
```

## 页面职责

1. 页面负责接收路由参数、组织页面状态、调用 API、处理主交互流程。
2. 页面可以保留主流程编排，不追求把页面拆成空壳。
3. 页面内已变长但仍属于当前页的逻辑，优先抽到页面私有 `helpers/` 或 `composables/`。
4. 只有真实复用或职责边界明显跨页面时，才提升为共享能力。
5. 删除或回退一个 UI 块时，要同步清理 template、script、style、imports、computed、handler 和文档引用，不只隐藏模板节点。

## 组件边界

1. 组件只承接清晰单一的 UI 职责。
2. 组件通过 props 接收稳定输入，通过 emit 抛出明确事件。
3. 组件不要拼页面路由、调用页面级接口、读取页面栈或决定登录流程。
4. 根公共组件不能依赖分包私有文件。
5. 模板块下沉成组件时，父页保留请求、分页、滚动、权限和主流程判断。
6. 组件拆分以降低阅读和维护成本为目标，不为了复用而复用。

## 展示模型

1. 复杂显隐判断不要堆在模板里。
2. 页面或组件内可以用 `view`、`stage`、`state` 这类 computed 模型集中组织展示字段。
3. 模板只消费稳定字段，例如 `showXxx`、`xxxText`、`xxxList`、`disabled`。
4. 展示模型只整理当前渲染需要的数据，不承接请求协议、路由规则或跨页面状态。
5. 当模板读取同一组字段超过多处时，优先收成一个展示模型，减少横向跳读。

## 请求规则

1. 所有 `uni.request`、`uni.uploadFile`、`uni.downloadFile` 都必须经过共享 API 层或平台适配层。
2. 页面不直接拼底层请求配置、鉴权头、公共 query、超时或错误码处理。
3. `content-type` 在请求层统一规范化，避免 `Content-Type` 和 `content-type` 混用。
4. 表单请求、空 body、URL query 传参、上传下载等特殊协议在请求层声明，不在页面散写。
5. 页面免登录和接口免登录分开控制；路由可进不代表页面内请求可以自动忽略 401。
6. 游客可访问的接口要在请求层显式关闭自动登录副作用。
7. 参数兼容、字段兜底和历史口径归一优先收口在请求层或边界 adapter。
8. 请求层不读取页面状态，不绑定具体页面 tab、滚动或弹窗状态。

## 异步与生命周期

1. tabbar 页面按缓存页处理，不能假设每次进入都会重新 `onLoad`。
2. `onLoad` 和首次 `onShow` 可能连续触发，同一请求需要单飞或去重。
3. 页面 `onShow` 中可以补刷新，但必须防止重复请求和旧数据覆盖。
4. 页面隐藏或卸载时，清理当前页面拥有的 timer、observer、轮询、订阅和未完成副作用。
5. 异步请求写回状态前，要确认当前页面、当前参数和当前请求 key 仍然匹配。
6. 对会被快速切换的请求使用 `requestSeq`、`requestKey` 或 `attempt` 隔离旧响应。
7. 提交中、支付中、保存中这类流程要冻结本次提交上下文，避免用户切换条件后旧任务写回新状态。
8. 登录成功、切账号、退出登录、401 失效后，需要明确哪些 store、本地缓存和页面态要刷新或清理。

## Watch 与首屏触发

1. 副作用 watch 绑定真实数据实体和必要上下文，不只绑定默认 index。
2. 首屏需要立即执行的副作用使用 `{ immediate: true }`。
3. watch 依赖应包含实体 id、类型、用户态、必要配置和路由参数。
4. 依赖未 ready 时不要提前启动会话、请求或统计段；等必要字段 ready 后再启动。
5. 当实体 id 或类型变化时，要显式重置旧列表、游标、loading、错误态和统计段。

## 路由与分享

1. 路由跳转统一使用完整路径，例如 `/pages/xxx_sub/page`。
2. query 编码统一交给 router/helper，页面不要手写重复 `encodeURIComponent`。
3. 路由边界可以兼容历史编码态，但内部状态应尽快恢复成原始值。
4. 分享路径必须能冷启动直达，不只验证站内跳转。
5. 分包页需要显式检查 `pages.json` 的分享配置和页面 `onShareAppMessage` / `onShareTimeline` 回调。
6. 分享截图期间如果临时隐藏浮动 UI，必须在 success、fail、complete 或兜底 timer 后恢复。
7. 页面不要依赖首页已初始化的 store；分享直达页必须能自行拉取必要上下文。
8. 新增路由前先检查是否可以复用既有详情、编辑或结果页，通过 query 区分上下文。

## 滚动与布局

1. 一个页面选定一个主滚动模型：原生页面滚动或 `scroll-view`，不要混用后再互相补丁。
2. 吸顶、触底、下拉刷新、锚点跳转和标题显隐都应围绕同一个滚动模型设计。
3. `scroll-into-view` 适合稳定锚点跳转；需要偏移时用隐藏 offset 节点，不要到处硬算 `scrollTop`。
4. `pageScrollTo` 和节点量位要在渲染完成后执行，并处理节点不存在。
5. `sticky`、`fixed` 和 `overflow` 在小程序端差异明显，改动时要验证真实端表现。
6. fixed 吸顶要补占位，避免内容跳动。
7. IntersectionObserver 不应是唯一判断来源；快速滚动场景可以用 scroll 事件兜底。
8. 列表触底分页要有 loading、hasMore、游标或页码保护，避免短列表首屏自动重复补拉。

## 小程序样式兼容

1. 不使用微信小程序 WXSS 不稳定的复杂选择器、通配符组合和 H5 专属写法。
2. 避免依赖 `> *`、过深选择器、动态标签选择器完成关键样式。
3. 页面级状态栏、导航栏样式应在 `pages.json` 和自绘导航中同步处理。
4. 多行省略、fixed、sticky、遮罩、层级和滚动容器样式必须在 mp-weixin 下验证。
5. 主题色、尺寸、间距优先使用局部变量或共享变量，不在多个节点散写同一组魔法值。
6. 结构性 UI 不依赖远程图片决定布局高度；需要量位时量真实容器节点。

## 状态与缓存

1. 页面临时 UI 状态默认留在页面或组件内部。
2. 跨页面、跨启动、需要统一清理的状态才进入 Pinia 或 settings store。
3. 小程序级持久配置收口到统一 store，不在页面散落 storage key。
4. 本地缓存 key 要有明确作用域，避免不同用户、不同上下文串数据。
5. store 初始值不要用假数据伪装已加载状态，避免首屏渲染误导。
6. 退出登录、切账号、401 失效、清缓存时要明确缓存保留和清理边界。

## 校验与变更记录

1. 每次改动至少运行 `git diff --check`。
2. 有统一脚本时运行 `npm run check` 或项目实际等价命令。
3. 没有统一脚本时，按影响文件执行可用的 `lint`、`type-check`、`node --check` 或构建命令，并说明缺口。
4. 分包、路由、分享、请求层、状态清理变更要验证主路径和冷启动直达路径。
5. 文档、规则、常量、触发时机和代码实现要同步更新，不能出现文档一套、代码一套。
6. 小修改可以不写长 plan，但要保留轻量变更记录，说明影响文件和验证方式。

## 明确避免

1. 不跨分包 import 私有组件或私有 helper。
2. 不把单次使用组件提前放到根 `components/`。
3. 不在页面散写请求头、公共参数、401 处理或上传下载细节。
4. 不让旧请求响应覆盖当前页面状态。
5. 不把模板变成复杂判断集合。
6. 不用路由参数和接口返回同时充当权威数据源。
7. 不把页面临时状态全部塞进 Pinia。
8. 不把调试日志、临时 timer、临时兜底字段留成正式逻辑。
9. 不用 H5 的滚动、样式、层级经验直接套微信小程序。
