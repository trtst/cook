## 适用范围

- `apps/client/src/pages/home/index.vue` 的首页四宫格入口
- `pages/recipe/index`
- `pages_pantry/index/index`
- `pages_meal/random`
- `pages_pantry/gap`

## 不在本轮范围

- 不改首页首屏三张主卡 `MAIN / SIDE_TOP / SIDE_BOTTOM`
- 不把首页改成动态流、聊天页或消息页
- 不在本轮冻结新的接口字段、聚合摘要接口或缓存策略
- 不在本轮细化视觉稿、动效稿和最终样式
- 不把四宫格改成动态排序或 `1 主 3 次`

## 已确认结论

1. 首页四入口继续保持固定四坑位，不改成动态布局。
2. 四宫格固定顺序为：`我想吃 / 问大家 / 随机 / 缺什么`；后台可按坑位上架/下架，首页只展示当前已上架入口。
3. 四个入口不是 4 个普通功能按钮，而是 4 个强中心：
   - `我想吃`：个人提案中心
   - `问大家`：家庭协商中心
   - `随机`：决策引擎
   - `缺什么`：执行落地中心
4. 首页入口名先保留当前口语化叫法；进入后的页面定位允许升级成更明确的语义标题。
5. 四宫格卡片不能只显示图标和标题；每个格子都必须同时表达：
   - 这个入口负责什么
   - 它当前处于什么状态
   - 用户点进去后立刻能做什么
6. 四宫格点入后的第一页必须是“场景首页”，不是空白页、纯列表页或单纯工具页。

## 首页卡片总规则

### 卡片结构

每个四宫格入口统一承载 4 层信息：

1. 固定入口名
2. 一句话定位
3. 当前最重要的一条状态
4. 一个明确主动作

### 信息优先级

首页卡片优先展示“当前动作价值”，而不是展示泛化介绍文案。

建议优先级：

1. 当前状态
2. 主动作
3. 固定定位

### 首页卡片禁区

- 只放图标和标题
- 长期展示不变的空副标题
- 把页面简介伪装成状态
- 展示与当前晚饭闭环无关的运营文案
- 做成聊天室、评论流或社区动态入口

## 四个入口的页面定位

### 1. 我想吃

- 首页入口名：`我想吃`
- 页面定位：`晚饭提案`
- 角色：把个人模糊欲望整理成家里可采纳的晚饭提议

#### 首页卡片推荐状态

- `把你今天想吃的先提出来`
- `你有 2 条想吃还没处理`
- `你的红烧排骨已进今晚候选`
- `今天先从一句感觉开始`

#### 首屏结构

1. 今日感觉区
   - `热乎的`
   - `下饭的`
   - `清爽的`
   - `省事的`
   - `正式一点的`
2. 提案方式区
   - `提一道菜`
   - `提一整套`
   - `从历史想吃里带入`
3. 最近提案区
   - 最近提过什么
   - 是否已被采纳
   - 是否还在等待处理
4. 去向区
   - `加入今晚候选`
   - `放进想吃池`
   - `发给主理人`

#### 关键动作

- 用一句话提想法
- 提一道菜
- 提一整顿饭
- 查看采纳状态
- 撤回或再次推荐

#### 核心边界

- 不把它做成普通收藏夹
- 不要求用户先理解“征集”和“想吃池”的区别
- 有征集时优先走当前征集；无征集时再沉淀到想吃池

### 2. 问大家

- 首页入口名：`问大家`
- 页面定位：`晚饭协商台`
- 角色：把一桌人的不同意见快速收口成今晚共识

#### 首页卡片推荐状态

- `把今晚这顿饭问清楚`
- `今晚征集中，还差 2 人没回`
- `面和饭打平，今晚需要拍板`
- `18:30 截止，可直接收口`

#### 首屏结构

1. 决策方式区
   - `全员投票`
   - `主理人拍板`
   - `二选一`
   - `每人报一道`
2. 当前分歧区
   - 谁想快一点
   - 谁想吃热菜
   - 谁偏向米饭或面食
3. 待回应区
   - 谁还没回
   - 何时截止
   - 当前是否可以催办
4. 收口动作区
   - `催一下`
   - `延长一下`
   - `现在生成建议菜单`

#### 关键动作

- 发起征集
- 切换决策模式
- 看谁没回
- 一键催办
- 一键收口

#### 核心边界

- 不只做票数列表
- 不把它缩成单次投票表单
- 协商的对象不仅是“吃什么”，还包括“怎么定”“何时收口”

### 3. 随机

- 首页入口名：`随机`
- 页面定位：`帮我决定`
- 角色：当没人想拍板时，先替一家人做一次收敛

#### 首页卡片推荐状态

- `没人想决定时，让它先帮你收一轮`
- `2 人晚餐，30 分钟内`
- `今天适合清冰箱`
- `投票打平，换个方式定`

#### 首屏结构

1. 约束条件区
   - `几个人`
   - `多久开饭`
   - `能不能买菜`
   - `想稳一点还是新一点`
2. 随机模式区
   - `最省事`
   - `最家常`
   - `最能清冰箱`
   - `最适合今晚`
3. 结果区
   - 一次给 3 套方案
   - 不给单一死答案
4. 调整区
   - `锁定一道`
   - `重摇其他`
   - `降复杂度`
   - `改成不出门`

#### 关键动作

- 设约束
- 产出 3 套候选方案
- 锁定并重摇
- 转成今晚候选
- 直接带去计划或征集

#### 核心边界

- 不做娱乐型摇一摇玩具
- 不输出脱离现实约束的假方案
- 候选不足时返回最佳可行结果，不强行补齐

### 4. 缺什么

- 首页入口名：`缺什么`
- 页面定位：`今晚能不能做`
- 角色：把已经决定的菜单推进到真正可执行

#### 首页卡片推荐状态

- `看看今晚这顿能不能顺利做起来`
- `还差 3 样，1 样可能家里还有`
- `现有食材已经能做 2 道`
- `补货有点麻烦，建议换一套更省事的`

#### 首屏结构

1. 结论区
   - `现在能做`
   - `确认一下能做`
   - `必须补货`
2. 缺口分层区
   - `确定缺`
   - `可能还有`
   - `可替代`
3. 解决方案区
   - `去买`
   - `换菜`
   - `问谁顺手带`
   - `先做能做的`
4. 成本区
   - `补齐大概多久`
   - `要不要出门`
   - `大概补几样`

#### 关键动作

- 看今晚能不能做
- 一键进购物清单
- 切换替代菜单
- 找人顺手补货
- 先做现有可做部分

#### 核心边界

- 不只做食材缺口计算器
- 不把所有问题都转成购物
- 缺口过大时要允许回退到替代菜单，而不是强迫采购

## 首页四宫格与页面标题关系

首页继续保留当前口语化命名，降低入口理解成本。

建议页面标题语义：

- `我想吃` -> `晚饭提案`
- `问大家` -> `晚饭协商台`
- `随机` -> `帮我决定`
- `缺什么` -> `今晚能不能做`

如果后续页面标题仍沿用旧叫法，至少也要在页面首屏用更明确的区块标题表达上述定位。

## 实施约束

1. 首先冻结页面行为，再决定是否需要新增摘要接口。
2. 当前 `home-entries` 仍只承担运营配置和跳转，不承载四宫格的运行时状态事实。
3. 四宫格卡片上的动态状态若要落地，必须按各自 owner 页面和业务事实单独确认来源，不能用兜底文案假装状态已存在。
4. 不为了首页四宫格引入聊天流、评论流、公开动态流或泛社区关系。

## 后续实施顺序

1. 先收口首页四宫格卡片的固定定位与状态表达。
2. 优先补强 `我想吃` 和 `问大家` 的场景首页。
3. 再补 `随机` 和 `缺什么` 的场景首页。
4. 页面行为冻结后，再分别确认接口摘要、埋点和空态。

## 验收标准

完成本执行单对应实现时，至少满足：

1. 首页四宫格继续使用固定四坑位，不出现动态排序；首页只展示当前已上架入口。
2. 四个入口都能在首页表达“定位 + 状态 + 主动作”，不再是纯标题导航。
3. 四个入口点入后的第一页都不是空白壳页。
4. 用户无需先理解内部术语，也能知道该入口现在能帮他完成什么。
5. 产品表达仍然围绕 `我想吃 -> 共同选择 -> 确认下一餐 -> 核对冰箱 -> 生成清单` 主链路，不漂移成社区产品。
