# 功能执行单：勋章墙与勋章模板管理

## 目标

- 本功能要跑通的最小业务闭环：用户在真实完成餐次、饭局与相关采购事实后，服务端自动点亮勋章；“我的”页展示勋章数量，勋章墙按类别展示全部勋章，点击进入勋章详情页，查看勋章说明与获得状态。
- 后台可管理勋章模板的上架、下架与展示信息，但不能直接给用户补发、撤销或修改已获得勋章。
- 对应 V1 范围：非货币、非任务中心、非运营裂变的个人荣誉记录，只记录真实做饭、开饭与已收录推荐事实。

## 本轮范围

- 小程序端：
  - “我的”页勋章入口与数量。
  - 勋章墙页面：分类 Tab、勋章宫格、灰态/高亮态。
  - 勋章详情页：勋章简介、类别、活动时间、获得时间。
  - 详情页右下角 `cookfont icon-notice` 说明入口与底部上滑说明。
- 后端 API：
  - 完成餐次、完成饭局、读取我的勋章墙。
  - 勋章模板读取、模板状态过滤、用户获得事实合并。
  - 保留自动发放逻辑，改为基于模板 code 与服务端确认事实派生。
  - 新增“推荐贡献”类勋章，当前只统计菜谱推荐收录和食材推荐收录。
- 后台管理：
  - 勋章模板列表、新增、编辑、上下架、归档。
  - 类别、名称、简介、说明文案、图标、排序、限定时间配置。
- 共享契约：
  - 勋章模板、勋章墙、勋章详情、后台勋章模板 DTO。

## 本轮不做

- 后台手动给用户发勋章、撤销勋章、改获得时间。
- 勋章进度条、连续打卡、差几次、任务中心、排行榜、分享裂变。
- 勋章佩戴、头像挂件、勋章兑换、会员专属勋章。
- 推送、弹窗、站内信等即时触达。
- 单位推荐收录勋章。当前单位推荐审核链路未实现，不纳入本轮统计。

### 业务流程

- 用户目标：
  - 在“我的勋章”里看到自己已获得和待获得的勋章。
  - 点开某枚勋章，查看它代表什么，以及如何获得。
  - 在推荐被系统真实收录后，自动点亮对应推荐贡献勋章。
- 触发条件：
  - 用户进入“我的”页点击勋章入口。
  - 用户点击勋章墙中的任一勋章。
  - 用户在详情页点击右下角说明 icon。
  - 用户完成真实餐次、饭局和相关采购事实后，服务端自动尝试派生勋章。
  - 用户的菜谱推荐或食材推荐被后台审核通过后，服务端自动尝试派生推荐贡献勋章。
- 主成功路径：
  - 后台提前配置可上架的勋章模板，包括类别、文案、图标、排序和限定时间。
  - 用户进入勋章墙，前端读取当前可见模板与本人已获得状态。
  - 勋章墙默认展示“全部”，可切换到 `开饭打卡 / 饭局协作 / 推荐贡献 / 节假日限定` 等类别。
  - 用户点击一枚勋章进入详情页，查看勋章简介和说明。
  - 用户点击详情页右下角 `icon-notice`，底部上滑展示“获取条件 / 所属类别 / 活动时间 / 获得时间”。
  - 用户在真实完成事实后再次进入勋章墙，可看到已获得勋章高亮显示。
  - 用户的菜谱推荐或食材推荐被后台审核通过后，服务端按累计收录次数自动点亮 `推荐新星 / 推荐之星 / 推荐大使`。
- 失败 / 阻断路径：
  - 未登录不能查看个人勋章页。
  - 非计划拥有者不能完成用餐。
  - 非饭局发起人不能完成饭局。
  - 已下架且本人未获得的勋章模板，不出现在用户勋章墙。
  - 已下架但本人已获得的勋章，仍作为历史荣誉可见。
  - 已归档模板不再对新用户开放获得；如已获得，仍可保留历史展示。
  - 限定勋章超出活动时间后停止新增获得，但已获得用户仍可查看。
  - 单位推荐当前没有真实审核收录链路，因此不计入推荐贡献勋章。
- 结束状态：
  - 计划餐次进入 `COMPLETED`。
  - 饭局进入 `COMPLETED`。
  - 用户勋章事实新增对应模板 code，后续重复达成不重复发放。
  - 勋章模板根据后台状态进入 `DRAFT / LISTED / UNLISTED / ARCHIVED` 中之一。
- 确认人 / 确认记录：
  - 2026-07-31 用户在当前对话确认勋章墙按类别展示、详情页独立、说明入口用 `cookfont icon-notice`。
  - 2026-07-31 用户确认顶部文案采用“认真做饭，也值得被记录”。
  - 2026-07-31 用户确认后台可以随时上架、下架勋章模板，但不做后台手动发放。
  - 2026-07-31 用户确认新增“推荐贡献”方向，先按真实已落地的菜谱推荐收录、食材推荐收录统计，不把单位推荐提前写进勋章事实。

### 页面行为

- 页面入口：
  - “我的”页勋章卡片。
  - 勋章墙页面勋章宫格。
  - 勋章详情页右下角说明 icon。
- 展示内容及用途：
  - “我的”页勋章卡片：显示已获得数量，作为勋章墙入口。
  - 勋章墙：
    - 标题“我的勋章”。
    - 副文案“认真做饭，也值得被记录”。
    - 已获得 / 总数摘要。
    - 类别 Tab：至少支持 `全部 / 开饭打卡 / 饭局协作 / 推荐贡献 / 节假日限定`。
    - 勋章宫格：未获得灰色，已获得彩色高亮。
  - 勋章详情页：
    - 勋章大图、名称、简短说明、所属类别。
    - 若为限定勋章，展示活动时间。
    - 页面底部展示获得时间或“尚未获得”。
    - 右下角固定 `cookfont icon-notice`。
  - 底部说明：
    - 上滑弹层展示“获取条件 / 所属类别 / 活动时间 / 获得时间”。
- 用户操作：
  - 点击勋章卡片进入勋章墙。
  - 点击类别 Tab 切换勋章分类。
  - 点击任一勋章进入详情页。
  - 点击详情页右下角说明 icon 查看获取说明。
  - 计划拥有者点击“完成用餐”。
  - 饭局发起人点击“完成饭局”。
- 加载 / 空态 / 失败态：
  - 勋章墙加载失败显示重试提示。
  - 若当前可见模板为 0，展示“勋章还在整理中”空态。
  - 若用户尚未获得任何勋章，仍展示全部模板，只是全部为灰态。
  - 未登录时显示登录引导。
- 成功后的页面变化：
  - 完成动作成功后，计划页即时刷新状态。
  - 返回“我的”页后勋章数量刷新。
  - 进入勋章墙后可看到新点亮勋章。
  - 进入详情页后可看到对应获得时间或未获得状态。
- 本流程不需要的页面数据：
  - 勋章进度百分比。
  - 还差几次。
  - 连续天数。
  - 会员权益引导。

## 领域与商业化评估

- 数据归属：
  - 勋章模板：`SYSTEM`
  - 用户勋章事实：`USER`
- Free 基础：全部首版勋章都可免费获得。
- 付费增量：本轮不做。
- 权益作用域：`不付费`
- 权益类型：`功能`
- 到期与超额行为：会员状态不影响首版勋章获得和保留。
- 数据保留与迁出：
  - 用户已获得勋章长期保留。
  - 模板下架或归档后，已获得用户仍保留历史可见性。
- 配置来源：
  - 模板展示配置：`ADMIN`
  - 获得事实：`SERVER_DERIVED`
- 隐私、安全与合规：
  - 勋章只由服务端基于真实完成事实和真实审核收录事实派生。
  - 后台不提供直接发放、撤回、改时间入口。
- 是否涉及 Reserved 的 OCR、AI、Pro 或多家庭：否。

- 验收方式：登录真实接口后，可在勋章墙切换类别、进入详情、打开说明。

### 后端确认

- 最小交付：
  - 勋章模板持久化。
  - 模板状态控制可见性与可获得性。
  - 用户勋章墙返回模板信息 + 获得状态。
  - 自动发放逻辑继续只基于真实完成事实和真实审核收录事实。
- 数据表 / 事务边界：
  - `MealPlanItem`、`DiningEvent`、`UserMedal`
  - 新增勋章模板表及其状态字段
  - 完成动作与发勋章仍在同一事务内
- 错误码：
  - `400`：饭局还没有任何已接受参与人，不能完成；模板时间非法；模板状态不允许当前操作。
  - `404`：资源不存在或无权限。
  - `409`：当前状态不允许进入完成态；模板 code 冲突。
- 不做项：后台发放、撤销、修改用户已获得勋章。
- 验收方式：接口测试脚本或手工请求完成链路后查询勋章墙列表与后台模板列表。
- 状态机 / 权限矩阵：
  - `MealPlanItem`: `PLANNED -> COMPLETED`
  - `DiningEvent`: `PLANNED -> COMPLETED`
  - `MedalTemplateStatus`: `DRAFT -> LISTED / ARCHIVED`，`LISTED -> UNLISTED / ARCHIVED`，`UNLISTED -> LISTED / ARCHIVED`
  - 计划完成只允许计划拥有者。
  - 饭局完成只允许饭局发起人。
  - 后台模板写操作只允许管理员。
- 配置解析与实例冻结：
  - 勋章模板是后台可变配置。
  - 用户勋章事实是不可回写的历史事实。
- 到期 / 清理任务：
  - 限定勋章通过 `startAt / endAt` 控制新增获得。
  - 本轮不做自动归档任务。
