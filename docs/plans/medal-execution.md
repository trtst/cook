# 功能执行单：勋章墙与勋章模板管理

## 目标

- 本功能要跑通的最小业务闭环：服务端根据真实完成事实自动点亮勋章；用户从“我的”页菜单入口进入勋章墙，按类别查看勋章，并进入详情页查看说明与获得状态。“我的”页不展示勋章数量。
- 后台可管理勋章模板的上架、下架与展示信息，但不能直接给用户补发、撤销或修改已获得勋章。
- 对应 V1 范围：非货币、非任务中心、非运营裂变的个人荣誉记录，只记录真实做饭、开饭与已收录推荐事实。

## 本轮范围

- 小程序端：
  - “我的”页保留“我的勋章”菜单导航入口与登录门禁；不显示勋章数量摘要。
  - 勋章墙页面：分类 Tab、勋章宫格、灰态/高亮态。
  - 勋章详情页：勋章简介、类别、活动时间、获得时间。
  - 详情页右下角 `cookfont icon-notice` 说明入口与底部上滑说明。
- 后端 API：
  - 完成餐次、完成饭局、读取我的勋章墙。
  - 勋章模板读取、模板状态过滤、用户获得事实合并。
  - 保留自动发放逻辑，改为基于模板 code 与服务端确认事实派生。
  - 新增“推荐贡献”类勋章，当前只统计菜谱推荐收录和食材推荐收录。
- 后台管理：
  - 勋章模板列表、新增、编辑、上下架、归档。
  - 类别、名称、简介、说明文案、图标、排序、限定时间配置。
- 共享契约：
  - 勋章模板、勋章墙、勋章详情、后台勋章模板 DTO。

## 本轮不做

- 后台手动给用户发勋章、撤销勋章、改获得时间。
- 勋章进度条、连续打卡、差几次、任务中心、排行榜、分享裂变。
- 勋章佩戴、头像挂件、勋章兑换、会员专属勋章。
- 推送、弹窗、站内信等即时触达。
- 单位推荐收录勋章。当前单位推荐审核链路未实现，不纳入本轮统计。
- 通用分享裂变奖励；回忆分享打卡按下方已确认的独立规则统计。

勋章墙分类展示名固定为：`MEAL_CHECKIN`「厨房日常」、`DINING_COLLABORATION`「饭局相聚」、`RECOMMENDATION_CONTRIBUTION`「好味分享」、`HOLIDAY_LIMITED`「节日限定」。首发分类保持四类，不把每一种统计方向拆成独立类别。

计数统一由服务端根据成功完成的业务事实派生。客户端不得直接提交勋章获得状态；勋章墙不提供进度条或“还差几次”。

### 回忆分享打卡

- 计数对象：饭局发起人。
- 前置条件：饭局已由发起人确认为完成；完成前打开回忆卡或分享不计。
- 计数事实：发起人主动触发微信回忆分享，且客户端分享菜单调用成功后，由服务端记录一次分享发起事实。
- 去重：同一场饭局最多计一次；重复打开回忆卡、重新生成快照、重新导出海报或再次发起分享都不重复计数。
- 五档候选阈值：`1 / 3 / 10 / 20 / 50` 场。
- 不计入：打开回忆卡、自动创建/更新快照、预览海报、生成海报、仅保存图片到相册。
- 平台事实边界：微信端能确认分享菜单已成功调起，但不能确认图片最终送达、对方打开或保存；勋章文案与获得条件按“发起分享”表述。
- 实现状态：新增 `POST /dining-events/{eventId}/memory-share-started` 记录发起事实；仍需完成定向验证和微信端人工验收。它不证明分享送达。

### 业务流程

- 用户目标：
  - 在“我的勋章”里看到自己已获得和待获得的勋章。
  - 点开某枚勋章，查看它代表什么，以及如何获得。
  - 在推荐被系统真实收录后，自动点亮对应推荐贡献勋章。
- 触发条件：
  - 用户进入“我的”页点击勋章入口。
  - 用户点击勋章墙中的任一勋章。
  - 用户在详情页点击右下角说明 icon。
  - 用户完成真实餐次、饭局和相关采购事实后，服务端自动尝试派生勋章。
  - 用户的菜谱推荐或食材推荐被后台审核通过后，服务端自动尝试派生推荐贡献勋章。
- 主成功路径：
  - 后台提前配置可上架的勋章模板，包括类别、文案、图标、排序和限定时间。
  - 用户进入勋章墙，前端读取当前可见模板与本人已获得状态。
  - 勋章墙默认展示“全部”，可切换到 `厨房日常 / 饭局相聚 / 好味分享 / 节日限定` 等类别。
  - 用户点击一枚勋章进入详情页，查看勋章简介和说明。
  - 用户点击详情页右下角 `icon-notice`，底部上滑展示“获取条件 / 所属类别 / 活动时间 / 获得时间”。
  - 用户在真实完成事实后再次进入勋章墙，可看到已获得勋章高亮显示。
  - 用户的菜谱推荐或食材推荐被后台审核通过后，服务端按累计收录次数自动点亮 `推荐新星 / 推荐之星 / 推荐大使`。
- 失败 / 阻断路径：
  - 未登录不能查看个人勋章页。
  - 非计划拥有者不能完成用餐。
  - 非饭局发起人不能完成饭局。
  - 已下架且本人未获得的勋章模板，不出现在用户勋章墙。
  - 已下架但本人已获得的勋章，仍作为历史荣誉可见。
  - 已归档模板不再对新用户开放获得；如已获得，仍可保留历史展示。
  - 限定勋章超出活动时间后停止新增获得，但已获得用户仍可查看。
  - 单位推荐当前没有真实审核收录链路，因此不计入推荐贡献勋章。
- 结束状态：
  - 计划餐次进入 `COMPLETED`。
  - 饭局进入 `COMPLETED`。
  - 用户勋章事实新增对应模板 code，后续重复达成不重复发放。
  - 勋章模板根据后台状态进入 `DRAFT / LISTED / UNLISTED / ARCHIVED` 中之一。
- 确认人 / 确认记录：
  - 2026-07-31 用户在当前对话确认勋章墙按类别展示、详情页独立、说明入口用 `cookfont icon-notice`。
  - 2026-07-31 用户确认顶部文案采用“认真做饭，也值得被记录”。
  - 2026-07-31 用户确认后台可以随时上架、下架勋章模板，但不做后台手动发放。
  - 2026-07-31 用户确认新增“推荐贡献”方向，先按真实已落地的菜谱推荐收录、食材推荐收录统计，不把单位推荐提前写进勋章事实。

### 页面行为

- 页面入口：
  - “我的”页“我的勋章”菜单项。
  - 勋章墙页面勋章宫格。
  - 勋章详情页右下角说明 icon。
- 展示内容及用途：
  - “我的”页仅显示“我的勋章”菜单导航入口，不显示已获得数量；登录门禁在入口层处理。
  - 勋章墙：
    - 标题“我的勋章”。
    - 副文案“认真做饭，也值得被记录”。
    - 已获得 / 总数摘要。
    - 类别 Tab：至少支持 `全部 / 厨房日常 / 饭局相聚 / 好味分享 / 节日限定`。
    - 勋章宫格：未获得灰色，已获得彩色高亮。
  - 勋章详情页：
    - 勋章大图、名称、简短说明、所属类别。
    - 若为限定勋章，展示活动时间。
    - 页面底部展示获得时间或“尚未获得”。
    - 右下角固定 `cookfont icon-notice`。
  - 底部说明：
    - 上滑弹层展示“获取条件 / 所属类别 / 活动时间 / 获得时间”。
- 用户操作：
  - 点击勋章卡片进入勋章墙。
  - 点击类别 Tab 切换勋章分类。
  - 点击任一勋章进入详情页。
  - 点击详情页右下角说明 icon 查看获取说明。
