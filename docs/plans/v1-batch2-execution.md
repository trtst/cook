# 炊火记 V1 第二批执行单

## 目标

第二批只在第一批稳定后启动。

本批目标是跑通：

`已安排 -> 做饭执行 -> 饭局完成`

本批只做：

1. 做饭执行
2. 饭局轻协作

## 一、开始条件

第一批必须同时满足：

1. 首页能正确引导用户下一步
2. 系统菜谱能顺畅保存为私房菜并加入计划
3. 缺口能正确写入采购清单

## 二、已冻结边界

### 做饭执行

- 多菜执行优先以 `做饭助手` 为主视图
- 原始步骤只做降级备选
- 前台三态固定为：
  - `未生成`
  - `已生成`
  - `降级原始步骤`
- 降级条件固定为：
  - 助手未生成
  - 助手生成失败
  - 助手版本与当前菜单不一致
- 本餐完成只能由用户显式点击触发
- 计划与饭局只有在显式完成后才同步完成

### 饭局轻协作

- 保留：
  - 发起
  - 邀请
  - 参与确认
  - 菜单确认
  - 我带菜
  - 完成饭局
  - 回忆分享
- 回忆分享能力在本批落地，但只在饭局完成后展示；分享卡展示字段暂不冻结，后续按详细设计单独确认
- `我想吃池` 与 `我带菜` 是并列模块，不互相替代
- `我想吃池` 按 `提议 + 附议 + 主家加入本次菜单` 落地
- `我想吃池` 只支持从已有菜谱中选择
- `我想吃池` 独立于主家菜单
- `确认菜单` 是唯一正式生效动作
- `我带菜` 只做登记，不进入采购、缺口、库存计算

## 三、本批要做什么

### 模块 4：做饭执行

- 做饭助手主视图落地
- 原始步骤降级链路落地
- 计时器可用
- 本餐完成状态收口

### 模块 5：饭局轻协作

- 发起 / 邀请 / 参与确认链路打通
- `我想吃池` 打通提议、附议和主家加入菜单
- `我带菜` 独立登记链路打通
- `确认菜单` 正式生效链路打通
- 饭局完成后可生成回忆分享

## 四、如何验证

### 做饭执行

- 进入做饭模式时，已生成状态优先看到做饭助手视图
- 在三类降级条件下，都能正确进入原始步骤视图
- 计时器可正常开始、结束和切换步骤
- 用户显式点击完成后，计划与饭局状态同步正确

### 饭局轻协作

- 发起人可发起饭局并邀请成员
- 参与人可确认参与
- 成员可提议菜谱、附议已有提议
- 主家可把提议加入本次菜单
- 确认菜单后，菜单正式生效
- 我带菜只做登记显示，不影响采购和缺口
- 饭局完成后才出现回忆分享入口并可生成分享卡；展示字段以后续详细设计确认为准

## 五、本批不做

- 聊天
- 实时同步
- 公开投票
- 我来做
- 做饭进度同步
- 共享冰箱
- 复杂权限
- 点菜池概念归一

## 六、一句话结论

第二批的任务不是加更多协作玩法，而是把：

**做饭执行 + 轻协作饭局**

做成一个能闭环的最小版本。
