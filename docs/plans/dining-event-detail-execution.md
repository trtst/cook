# 功能执行单：饭局详情页第二批收口

## 说明

本文档已按最新 V1 执行基线重写。

当前饭局详情页只以以下文档为准：

- `docs/plans/v1-execution-baseline.md`
- `docs/plans/v1-batch2-execution.md`

旧版“待认领 / 认领 / 释放 / 我来做”语义已退出 V1，不再作为详情页执行目标。

## 目标

饭局详情页本轮只跑通以下闭环：

- 查看饭局主信息、参与人、菜单
- 参与人通过 `我想吃池` 提议菜谱、附议已有提议
- 发起人把池子里的菜 `加入本次菜单`
- 参与人单独登记 `我带菜`
- 菜单缺口继续进入采购
- 做饭助手继续承接已确认菜单
- 饭局完成后展示回忆分享入口

## 当前范围

### 小程序端

- `pages_meal/detail`
  - 菜单区只展示主家菜单，不再展示掌勺认领状态
  - 新增 `我想吃池` 面板
  - 保留独立 `我带菜` 面板
  - 发起人可从 `我想吃池` 把菜加入本次菜单
  - 参与人可提议、附议、取消附议
  - footer 在菜单编辑阶段对参与人展示 `我想吃 + 我带菜`

### 后端 API

- 保留现有：
  - `POST /api/dining-events/:eventId/bring`
  - `POST /api/dining-events/:eventId/share-link`
- 新增最小接口：
  - `POST /api/dining-events/:eventId/wishes`
  - `POST /api/dining-events/:eventId/wishes/:wishItemId/support`
  - `POST /api/dining-events/:eventId/wishes/:wishItemId/menu`
- 旧 `POST /api/dining-events/:eventId/cook` 不再作为 V1 前台主流程接入

## 明确不做

- 我来做
- 掌勺认领 / 释放
- 聊天、实时同步、公开投票
- 共享冰箱、共享采购、复杂权限
- 我想吃自由输入
- 点菜池概念归一

## 页面行为冻结

- 菜单区：
  - 只看主家已确认菜单
  - 右侧状态位只做被动展示，不再可点击认领
- 我想吃池：
  - 参与人从已有菜谱里选一道放入池子
  - 其他参与人可对现有提议附议
  - 发起人可把某道提议加入本次菜单
  - 池子独立于主家菜单，不直接并入
- 我带菜：
  - 继续单独登记
  - 不进入主家菜单
  - 不进入采购、缺口、库存计算

## 最小验收

1. 进入饭局详情页，能看到 `菜单 / 我想吃池 / 带菜 / 采购准备 / 做饭助手`
2. 参与人可提交一道 `我想吃`
3. 参与人可附议和取消附议
4. 发起人可把某条 `我想吃` 加入本次菜单
5. `我带菜` 继续只做登记显示
6. 页面中不再出现 `待认领 / 认领 / 释放 / 我来做`

## 一句话结论

饭局详情页第二批的任务不是继续扩协作玩法，而是把：

**主家菜单 + 我想吃池 + 我带菜**

收成符合最新 V1 的最小轻协作详情页。
