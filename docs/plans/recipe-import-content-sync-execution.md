# 系统菜谱批量同步导入正文执行单

## 已确认流程与页面行为

- 系统菜谱列表新增独立的“批量同步导入正文”操作，按已选择菜谱调用；与“一键确认候选”保持独立。
- 仅同步导入 JSON 的名称、故事、食材与用量、厨具、关键词、步骤正文和步骤图片提示词。
- 保留菜谱分类、基准人数、难度、时长、小贴士、封面图、步骤图和当前完整 Wiki；正文变化创建不可变新版本，旧版本及固定引用保留。
- 每道菜必须唯一关联一条已发布导入记录。来源不明确、结构化匹配不完整、步骤数量不同，或现有步骤图无法按序安全对应时跳过并报告原因。
- 每批最多 100 道，逐条返回同步或跳过结果；接口要求超级管理员与幂等键。

## 权限、状态与实现边界

- 目标仅限 ACTIVE 系统菜谱；请求 ID 去重并限制为 1–100 个。
- 服务端重新检查导入关联、正文版本和菜谱版本，在事务中创建新版本并以旧 `currentVersionId + version` 条件更新当前指针。
- 原 Wiki 的人工标签、助理候选/快照、Wiki 步骤图与已消费解锁权复制到新版本；自动标签根据新正文重新计算。复制的解锁权不重复计入每日额度；未完成的预约不复制。营养快照根据新正文重新计算。
- 不改分类、不重建菜谱、不覆盖任何正式图片、不修改导入记录、不执行存量数据回填。

## API 与页面

- `POST /admin/recipes/content/sync-import`：`{ recipeIds: number[] }`，幂等键在请求头；返回计数和逐条结果。
- Admin 系统菜谱列表使用已选择菜谱 ID，显示跳过原因；候选确认功能继续执行 Wiki 候选确认。

## 验收范围

- 静态检查 API/Admin 类型和 OpenAPI 契约，检查目标 diff。
- 不执行测试库或线上数据操作；登录态后台验收与真实存量回填在实现后另行进行。
