# 功能执行单：菜谱食材角色与智能标签

> 状态：已确认先在 TEST 为所有未删除菜谱的当前版本推导并写入角色；复用现有 `ingredientsJson` 与 Wiki 原位修订能力，不新增表或枚举。

## 目标

- 为每个菜谱中的食材条目标记其在该菜谱里的角色，避免把葱、姜、蒜等调味料误当作菜品主体。
- 为智能推荐、周刊编排和菜谱标签生成提供可信的结构化输入。
- 不在“我的菜谱 / 灵感菜谱”列表新增筛选项；不改变食材自身的全局分类或属性。

## 当前实施范围

- 更新 `docs/plans/recipe-admin-json-conversion.md`，明确每道菜 JSON 的每条食材带 `recipeRole`。
- 同步 `docs/plans/recipe-data-completion-rules.md`，明确角色是菜谱上下文，不是全局食材属性。
- 菜谱 JSON 导入校验并保存 `ingredients[].recipeRole`；角色限定为 `MAIN / ACCOMPANIMENT / SEASONING`。
- Wiki 修订支持只改 `ingredientRoles`，不重建食材用量、营养快照或反向索引；沿用 SUPER_ADMIN 原位修订与审计。
- TEST 批量修复范围为 ACTIVE/BLOCKED 菜谱当前版本；DELETED 菜谱和未发布 RecipeDraft 不处理。
- 不在全局 `Ingredient` 上增加“主料 / 配料 / 调味料”属性；`isStaple` 仍表示主食类食材。

## 业务流程与页面行为门禁

### 业务流程

- 用户目标：为菜谱逐条标注主料、配料、调味料，供智能推荐、周刊编排和标签推导使用。
- 主成功路径：先生成只读预览；校验状态、当前版本和正文摘要未变化后，通过 Wiki 角色修订写入并重算自动标签。
- 失败 / 阻断路径：报告与数据库当前内容不一致、食材行无法逐行匹配或写入被拒绝时停止，不套用旧建议。
- 不包含：新增面向用户的菜谱列表食材筛选控件。

### 角色含义草案

| 展示名 | 建议代码 | 含义 | 推荐/周刊用途 |
| --- | --- | --- | --- |
| 主料 | `MAIN` | 决定菜品主体或主要蛋白的食材 | 优先生成主要食材和主蛋白标签 |
| 配料 | `ACCOMPANIMENT` | 与主料共同构成菜品的蔬菜、豆制品等 | 可参与食材多样性、菜品结构标签 |
| 调味料 | `SEASONING` | 主要用于调味、增香、上色的食材 | 排除出菜品主体和主要食材推断 |

角色只改变菜谱标签和推荐/周刊的解释方式；不能从菜谱正文中删除任何食材。营养、实际用量、购物准备和菜谱详情仍保留全部食材。

### 页面行为

- 不新增页面或列表筛选项；角色供现有自动标签与后续智能推荐/周刊使用。
- 每条食材都必须按菜谱自身语义推导角色；角色不留空、不标记 `NEEDS_FIX`。
- 置信度和判断依据仅用于只读预览，不写入菜谱正文。
- AI 不属于当前阶段；未来如纳入，须另行确认项目保留范围及候选确认流程。

## 领域与商业化评估

- 数据归属：菜谱正文归菜谱版本；每个角色是菜谱食材关系的上下文属性，不是 `Ingredient` 的全局属性。
- Free / 付费：不改变现有菜谱权限、数量配额或权益作用域。
- 隐私、安全与合规：查询继续遵守现有菜谱可见范围；不扩展公开发现范围。
- Reserved：不涉及 OCR、AI、Pro 或多家庭。

## 当前接口契约

| 方法 | 路径 | 用途 | 状态 |
| --- | --- | --- | --- |
| 现有后台菜谱导入接口 | 接受 `ingredients[].recipeRole` | `MAIN / ACCOMPANIMENT / SEASONING` |
| 现有 Wiki 修订接口 | `fields=["ingredientRoles"]` | 只替换当前版本每条食材角色，按 ID 和名称逐行匹配 |

- 不新建菜谱列表筛选参数或通用“食材搜菜谱”接口。
- 不改变已有 `keyword` 查询含义。

## 数据约束

| 主事实 / 关系 | owner | 必要字段 | 生命周期 | 是否复用现有结构 |
| --- | --- | --- | --- | --- |
| 菜谱版本食材条目 | 菜谱固定版本 | `ingredientId`、角色、名称/用量快照 | 随不可变正文版本固化 | 复用 `ingredientsJson` |
| 菜谱版本自动标签 | 菜谱固定版本 | 现有 `RecipeVersionTag` 结构 | 根据角色重算并保留 source/status | 复用现有版本标签，不新增通用标签表 |

- 历史角色按菜谱语义推导；不持久化 `NEEDS_FIX`、置信度或全局食材角色。
- 不新增全局食材角色字段；不默认扩展 `RecipeVersionIngredient`，除非已确认的真实推荐/周刊查询证明需要。
- 写入报告绑定 `recipeId + contentVersionId + 正文摘要`，防止对已变化内容套用旧推导。
- 不改周刊发布条件；角色只影响候选标注、统计和提示，除非后续另行确认规则。

## 已发现的版本边界与建议

- 菜谱内容版本是固定版本。角色回填通过 SUPER_ADMIN Wiki 的 `ingredientRoles` 显式原位修订，保持版本 ID 并记录审计；已引用该版本的周刊、收藏、计划或饭局会读取新角色。
- 现有 `RecipeVersionTag` 已有 `PRIMARY_INGREDIENT / MAIN_PROTEIN_TYPE / DISH_ROLE`，并支持 `AUTO / USER / OPS / AI` 来源及 `CONFIRMED / CANDIDATE / NEEDS_REVIEW` 等状态；优先复用它承接下游标签，不新增第二套菜谱标签表。
- 当前主要食材推断在找不到已识别蛋白时会回退到正文食材顺序的前几项，角色数据可以替代这个不稳定回退。
- 不增加自动 AI 分类服务；规则推导报告可列出置信度和依据，但持久化时每条食材都必须落为一个明确角色。
- 已按只读候选报告实施 TEST 回填；报告按角色分类与内容摘要绑定，未匹配的报告或版本变化会拒绝写入。
