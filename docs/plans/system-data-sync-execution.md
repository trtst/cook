# 后台系统数据手动同步

## 目标与确认范围

在后台使用一个统一 JSON 数据包手动导出、校验、预览和导入系统基础数据，先用于测试环境到线上，后续用于线上到测试环境。数据包格式版本固定为 `cook.system-data.v1`。

本轮包含：系统菜谱分类、系统菜谱当前正文及 Wiki/营养/质量快照、系统食材分类、系统食材、系统单位、营养食品及食材营养关联和单位换算。

明确排除：私房菜、个人食材、用户账号和其他用户私有数据；不做自动同步、增量版本历史、数据包缺失项删除和数据库级备份恢复。

## 业务流程与页面行为

- 导出：管理员从“基础数据同步”页面下载带 `schemaVersion` 和 `exportedAt` 的 JSON。
- 预览：选择不超过 10 MB 的 JSON；服务端校验格式、统计新增/匹配 ID 的记录，并提示个人数据 ID 冲突与不可变正文版本冲突。
- 导入：管理员确认预览后，服务端在一个事务中写入；任一唯一键、外键或内容冲突整体回滚。
- 覆盖规则：按 ID 新增或覆盖；数据包缺失的目标数据保留，不删除。
- 方向规则：必须配置 `SYSTEM_DATA_ENVIRONMENT=TEST|ONLINE`。线上仅允许导入测试数据一次；测试环境只接受线上数据包。
- 菜谱归属：不导出账号资料；系统菜谱写入时映射到目标环境公共内容池账号。
- 图片：图片 URL 保留原值，图片文件本身不进入 JSON 数据包。
- 权限：仅 `SUPER_ADMIN` 可访问；导入写操作使用数字字符串 `Idempotency-Key`。

## 实现边界

- API：`GET /admin/system-data/export`、`POST /admin/system-data/preview`、`POST /admin/system-data/import`。
- Admin：新增“基础数据同步”页，提供导出、选包校验、数量预览、冲突提示、确认导入和失败提示。
- 数据库：不新增表、字段、索引或 migration；导入完成后同步显式 ID 表的序列值。
- 事务：导入只写入同步包中的平台数据，不清理包外记录；不得触碰私房菜、个人食材及个人表。

## 已知限制

跨环境的图片文件没有随 JSON 移动。如果环境使用不同的图片对象存储，导入后的图片地址仍指向导出环境，需要另外迁移媒体文件。
线上部署需将 `SYSTEM_DATA_ENVIRONMENT` 配为 `ONLINE`，测试部署配为 `TEST`；未设置或值无效时同步接口拒绝操作。
