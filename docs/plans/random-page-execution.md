# 随机一桌 V1 最终规则

## 一、功能定位

随机一桌是一个低决策成本的菜单推荐功能：系统按当前餐次、人数、冰箱和用户限制生成一桌菜，用户可以逐道调整，最后保存到计划。

- 不是纯抽签工具。
- 不是聊天产品。
- 不新增随机收藏、随机历史或独立随机结果表。

## 二、餐次与菜位

公共餐次共五个：早餐、午餐、下午茶、晚餐、夜宵。

随机一桌 V1 只支持：早餐、午餐、晚餐。

### 早餐

默认生成：

- 早餐主食 1 道
- 早餐蛋白 1 道
- 早餐小菜 1 道
- 早餐菜位数量不随人数增加，人数只影响份量；不限制早餐人数，也不强制改选午餐。
- 用户可通过加菜调整当前早餐菜单。

首次进入随机页默认选择当前可用餐次和 2 人；再次进入时保留用户上次的餐次、人数和冰箱选择。

### 午餐和晚餐

汤和主食不计入菜数。

```text
dishCount = peopleCount + 1
荤菜数 = ceil(dishCount / 2)
素菜数 = floor(dishCount / 2)
```

- 荤菜包含肉类和水产类主菜。
- 3 人以下：汤可选，默认不生成。
- 3 人及以上：默认生成 1 道汤。
- 主食默认 1 道；1 至 2 人可选，3 人及以上必含。
- 用户加菜、删菜只影响当前这一桌。

## 三、候选来源与比例

候选来源必须同时包含：

- 我的菜谱
- 灵感菜谱

每个菜位独立计算候选池，不混合菜位类型。

| 菜位 | 我的菜谱 | 灵感菜谱 |
| --- | ---: | ---: |
| 荤菜 | 70% | 30% |
| 素菜 | 50% | 50% |
| 汤 | 50% | 50% |
| 主食 | 60% | 40% |
| 早餐蛋白 | 70% | 30% |
| 早餐小菜 | 50% | 50% |
| 早餐主食 | 60% | 40% |

来源数量按目标需求数做整数分配：先取各自比例的整数部分，剩余数量按小数部分从大到小补齐；相同小数时优先“我的菜谱”。

- 一侧不足时，由另一侧补齐。
- 两侧都不足时，菜位留空。
- 不跨菜位、不跨类型、不使用不符合条件的菜强行补齐。
- 只有已发布、允许曝光、随机标签齐全的固定菜谱版本才能成为候选。

## 四、筛选与排序

### 硬过滤

所有候选必须通过：

- 用户过敏和严格忌口。
- 当前餐次。
- 当前菜位类型。
- 本轮未出现。
- 当前换菜操作的硬限制。

安全条件不能因候选不足而放宽。

### 软排序

排序优先级：

1. 冰箱匹配率：`HIGH`、`MEDIUM`、`LOW`、`UNKNOWN`。
2. 最近未吃。
3. 荤菜主蛋白不重复。
4. 快手程度。
5. 同分时允许有限随机扰动。

“最近未吃”查询最近 14 天的已确认计划和完成记录，不新增随机历史。

## 五、推荐理由

- 每道菜展示一条短理由。
- 理由必须来自实际命中的排序信号。
- 优先使用：`冰箱里有`、`最近没吃`、`搭配互补`、`做起来快`。
- 没有可靠信号时显示：`推荐尝试`。
- 理由只说明该菜命中的一个真实优势，不代表唯一或最高权重的推荐原因。
- 前端不能自行猜测或拼接不存在的理由。

## 六、本轮交互

| 操作 | 规则 |
| --- | --- |
| 换一道 | 替换当前菜位，优先同来源、同类型；原菜本轮不再出现；原来源耗尽后允许另一来源补位 |
| 划掉 | 移除当前菜位，不补位；原菜本轮不再出现 |
| 锁定 | 固定当前菜位，再来一桌时保留 |
| 再来一桌 | 只重算未锁定菜位，保留锁定菜和本轮排除项 |
| 确认这桌 | 进入保存计划流程，本轮状态结束 |

- 换一道、划掉不扣生成次数。
- 生成一桌、再来一桌各扣一次生成次数。
- 随机页不逐个确认食材库存，只自动展示冰箱匹配和缺口信息。

## 七、登录与次数

- 未登录点击生成、再来一桌或冰箱相关按钮时，呼起登录。
- V1 先限制生成次数，不接会员、积分、次数兑换或大模型计费。
- V1 默认 7 天窗口 21 次，具体额度由后台接口提供，前端不写死。
- 次数由服务端校验和扣减，前端只展示服务端返回结果。

## 八、保存到计划

- 随机一桌最终只保存到计划。
- 保存时记录固定的菜谱内容版本。
- 计划后续支持复制。
- 冰箱缺口按实时库存重新计算。
- 随机页不直接创建或写入购物清单，采购从计划继续。
- 已保存的计划由计划历史承接，不新增随机历史。

## 九、空态与候选不足

- 随机页不展示整页“暂无内容”空状态。
- 首次进入只展示条件区和主引导。
- 单个菜位无候选时保留菜位位置并显示明确提示。
- 不为填满页面而绕过安全条件、来源比例或菜位类型。

## 十、V1 必须完成

1. 同时查询我的菜谱和灵感菜谱，并保留来源与固定版本语义。
2. 按菜位执行来源比例、整数分配、补位和空位规则。
3. 补齐餐次、菜位、主蛋白、主要食材和风味等结构化候选事实。
4. 完成硬过滤、冰箱匹配、最近未吃、蛋白多样性和有限随机排序。
5. 返回每道菜真实且唯一的一条推荐理由。
6. 完成生成、换一道、划掉、锁定、再来一桌的本轮状态管理。
7. 接入服务端次数和未登录登录门禁。
8. 将确认结果保存为固定版本计划。
9. 处理候选不足、空菜位、网络失败、未登录和次数耗尽提示。

## 十一、V1 不做

- 会员、积分和次数兑换。
- 大模型参与普通随机生成。
- Chat-first 入口、天气推荐、RAG、向量库和图数据库。
- 独立随机历史、随机收藏、随机结果持久化。
- 随机页直接采购。
- 用菜名字符串代替食材事实做过敏判断。
- 为补齐数量而跨菜位或跨类型补菜。

## 十二、验收标准

- 早餐、午餐、晚餐的菜位和数量符合本规则。
- 来源比例、补位和空位符合本规则。
- 过敏、忌口、餐次、菜位类型和本轮重复候选不会进入结果。
- 推荐理由与真实排序信号一致。
- 换菜、划掉、锁定和再来一桌状态正确。
- 生成和再来一桌扣次数，局部换菜不扣次数。
- 未登录操作均进入登录流程，额度由后台结果决定。
- 确认后保存固定版本计划，计划可继续使用实时冰箱缺口。
- 页面没有整页空状态，候选不足只提示对应菜位。
