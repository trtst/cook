# 食材痕迹分类筛选与分页执行单

## 确认范围

- 用户确认：食材参考页显示正式食材分类；选分类后由服务端筛选；每页 20 条，触底追加；下拉刷新当前分类。
- “全部”不传分类 ID，并包含没有关联到当前正式分类的历史痕迹。
- 分类选项来自 `GET /ingredient-categories`，即使某分类当前没有痕迹也保留选项。
- 已加载页缓存在当前页面内存，按登录用户和分类隔离；页面重新显示复用内存数据，下拉刷新当前分类；不写本地持久化。
- 管理模式“全选”先加载完当前分类结果，再选择可见范围，保持全选语义。

## 本轮范围

- Client：`pages_pantry/index/index.vue`、`apis/fridge.ts`。
- API：为 `GET /fridge-traces` 增加可选 `categoryId`；在 SQL 汇总前按当前食材分类筛选，返回继续使用现有分页结构。
- 文档：同步 API 契约和中心变更日志。
- 不改 Prisma、SQL schema、migration、权限边界或冰箱痕迹的业务状态规则。

## 页面与接口行为

- 切换分类时回到列表顶部并清除选择；优先复用该用户该分类的内存分页，未缓存时从第一页请求。每页请求 `pageSize=20`；仅在 `hasNext` 时触底取下一页。
- 未分类或无法关联当前正式分类的历史痕迹只在“全部”出现。
- 下拉刷新替换当前分类缓存并回到第一页；分页失败保留已加载结果，可点提示重试。
- `GET /fridge-traces` 仍是当前用户的分页摘要查询，`categoryId` 只影响筛选，不新增响应字段。
