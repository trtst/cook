# 功能执行单：饭局准备状态与详情取消入口

## 目标

- 按 `docs/superpowers/specs/2026-09-24-shopping-fridge-low-maintenance-v1-design.md` 落地饭局备齐/开始做饭、准备预览和计划/饭局取消入口。
- 用户已明确授权最小 API 与数据库状态变更。

## 本轮范围

- 小程序：饭局采购面板展示“已备齐”；逐项“家里有，不用买”；全部准备完成后主操作为“开始做饭”，开始后为“结束饭局”；移除采购预览菜谱来源名；详情正文底部按时间展示取消入口。
- 后端：饭局逐项准备记录、整顿“已备齐”时间、开始做饭时间；计划取消状态及受保护写接口；准备状态由当前菜单固定版本与购物状态计算。
- 数据：饭局准备行按 `diningEventId + sourceKey` 唯一；`ShoppingItem.BOUGHT` 仍是已购买事实，不复制到准备表。饭局级“已备齐”和“开始做饭”使用时间事实。计划取消保留计划、菜单和历史，开放同日同餐次的新计划。

## 本轮不做

- 不改变 `meal-footer-panel` 布局。
- 不改菜单确认、结束饭局、结束后更新食材/分享回忆既有流程。
- 不以“家里有”写长期冰箱状态或数量。
- 不加入库存缺口计算、自动扣减或计划/饭局的恢复入口。

## 业务流程与页面行为门禁

### 业务流程

- 饭局主家可以在采购面板直接确认本顿已备齐，跳过购物清单；也可以逐项将饭局来源食材标记为“家里有，不用买”。清单“已买”沿用既有购物事实。准备状态仅属于当前饭局。
- 当前菜单所有准备项处理完成后，主操作显示“开始做饭”；开始后显示“结束饭局”。状态写入由饭局主家发起，需数字字符串幂等键，并在事务中校验饭局状态与权限。
- 计划由所有者取消时保留计划内容、独立进入 `CANCELLED`，不进入完成后的食材更新或回忆流程；取消后仍可为同一日期/餐次创建新计划。已到计划日期结束后拒绝取消。
- 饭局取消继续使用已冻结的发起人、无人接受、未到开席时间规则。

### 页面行为

- 饭局采购面板预览仍显示食材名与用量，删除来源菜谱名；每项支持“家里有，不用买”切换，已买状态由清单回写的购物状态反映。
- “已备齐”保留为不进入清单的一键操作。全部准备完成后主操作显示“开始做饭”；开始后主操作显示“结束饭局”。
- “取消饭局 / 取消计划”移到详情正文末尾，达到对应时间后隐藏；取消饭局继续二次确认。取消计划不删除计划内容。

### 门禁结论

- [x] 业务流程与页面行为已由用户确认的 V1 基线覆盖；用户另行批准最小 API/数据库状态。
- [x] 现有页面、接口和模型仅作为候选实现；其状态不够表达逐饭局准备和计划取消。

## 权限、状态和接口

| 方法 | 路径 | 用途 | 权限 | 幂等 | 状态 |
| --- | --- | --- | --- | --- | --- |
| GET | `/dining-events/{eventId}/shopping-gap` | 返回当前饭局菜单食材及准备状态 | 主家/已接受参与人读取 | 否 | 扩展响应 |
| POST | `/dining-events/{eventId}/preparations` | 按稳定来源键设置/撤销“家里有” | 饭局主家 | 是 | 新增 |
| POST | `/dining-events/{eventId}/prepare` | 一键确认本顿全部备齐 | 饭局主家 | 是 | 新增 |
| POST | `/dining-events/{eventId}/start-cooking` | 备齐后记录开做时间 | 饭局主家 | 是 | 新增 |
| POST | `/meal-plans/{planItemId}/cancel` | 保留计划并标记取消 | 计划所有者 | 是 | 新增 |

## 最小数据表与约束

| 主事实 | owner | 必要字段 | 生命周期与约束 | 对应查询 |
| --- | --- | --- | --- | --- |
| 饭局某个固定菜单食材确认“家里有” | 饭局 | `diningEventId`, `sourceKey`, `confirmedByUserId`, `confirmedAt` | 饭局删除时级联；`UNIQUE(diningEventId, sourceKey)`；撤销时删除确认行 | 饭局采购准备预览 |
| 饭局整体备齐、开始做饭时间 | 饭局 | `ingredientsReadyAt`, `cookingStartedAt` | 饭局状态转换事务写入；不推导长期食材状态 | 饭局详情与动作可用性 |
| 计划取消状态 | 计划 | `status=CANCELLED`, `cancelledAt` | 保留菜谱/菜单；同日期餐次只允许一条 `PLANNED` | 计划列表和详情 |

- 已买状态从现有 `ShoppingItem.status=BOUGHT` 推导，不在准备表重复保存。
- 不新增通用 JSON、缓存或长期库存记录。

## 联调与验收

- [ ] 饭局不同食材行可独立标记/撤销“家里有”；同食材出现在两个饭局时互不影响。
- [ ] 购物清单勾选“已买”后，返回饭局详情可见准备进度更新；取消勾选后重新变为待准备。
- [ ] “已备齐”无需创建或打开购物清单即可启用“开始做饭”。
- [ ] “开始做饭”持久化；重新进入仍显示“结束饭局”。重复提交不重复写入。
- [ ] 采购预览不展示菜谱来源名。
- [ ] 计划取消保留菜单并区分于完成；同日期餐次可以另建计划；计划日结束后拒绝取消。
- [ ] 饭局取消入口在预定开席时刻后隐藏，服务器拒绝过时取消。
- [ ] 未登录、非所有者/非主家、取消/完成对象的写操作失败。
