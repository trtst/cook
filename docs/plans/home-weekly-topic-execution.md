## 共享周刊按日菜单闭环

### 目标与边界

- 平台按北京时间自然周维护共享周刊，每期覆盖周一至周日；已发布期免费浏览并可转发给微信朋友。
- 后台逐日编排菜谱，支持草稿、预约上架、已上架编辑、下架后转草稿；只有草稿可删除。
- 小程序按服务端周期和星期展示当日菜单；单道菜及当日批量菜沿用加入计划菜单，不新增整周加入。
- 菜谱失去公开资格时前台隐藏该菜，不影响周刊和其他日期浏览；后台可替换或忽略该条运营待办。
- 本阶段不含个人周刊、个性化推荐、服务端模型集成、会员、付费、炊火币、签到、分享统计和通用任务中心。已另行确认并实现 Codex 批量选题补充流程：超级管理员通过后台 Bearer 认证读取统计、搜索候选并预览/导入 JSON；导入只创建草稿。测试环境首期草稿已生成并导入；真实线上凭证验收及运营人工审核仍待完成。

### 主流程与状态门禁

1. 运营创建草稿并按星期分配菜谱；七天都至少有一道符合公开条件的菜，才可立即上架或预约上架。
2. 预约只附着草稿；到期后 Worker 按预约时间发布。周期周一可在后台编辑；新建时留空默认下周。调整/取消预约和实际发布都保留周期。
3. 已上架内容原期编辑；重大错误可下架。下架期须先转草稿再重新上架或删除。
4. 首页当前期按最新周期选择；打开本期时优先选择今天对应的星期（只选择有可公开菜单的日期），没有今天对应的菜单时回退到周一，周一也不可用则选第一个有菜单的日期；打开往期固定选周一。Client 使用 API 返回的周期日期，并按北京时间确定今天对应的星期。
5. 周刊分享定位整期，不携带当前所选日期或个人信息；标题为日期范围和周刊标题，封面缺失时使用产品 Logo。
6. 失效菜谱在公开读取中隐藏。运营待办针对具体周刊菜谱项，可换菜或忽略；未替换不阻断周刊浏览。

## 菜谱库快照与每期菜单检查（口径已确认）

- 菜谱库快照回答公开菜谱供给是否支持编排；来源为 `PUBLIC_INSPIRATION`，分母是快照生成时符合 `publicInspirationRecipeWhere("ACTIVE")` 的公开当前版本数。快照手动重建并持久缓存；重建失败保留最近成功快照。
- 库快照每个维度返回有至少一个已确认值的菜谱数、无已确认值的菜谱数、覆盖率、每个桶的唯一菜谱数、占总数比例和占已确认数比例。多标签桶允许交叉。营养返回四种现有状态及热量/蛋白质/脂肪/碳水的逐字段覆盖，不生成健康分。
- 周刊检查回答指定期的实际选菜结构；由 `GET /admin/home-topics/{topicId}/menu-check` 读取或生成，并按 `topicId + topicVersion` 持久缓存。同版本快速返回；缺失或旧版本时使用该期固定菜单重建并替换。后台编辑页在版本不一致时把旧结果显示为 `stale`。
- 周刊检查按日和整周统计菜数、去重数、角色、食材、蛋白、做法、难度、时长和覆盖率。覆盖率分母是当天或整周实际入选的去重菜谱数。重复菜只作为完整性异常；连续两天主要食材相同只在相关标签已确认时提示。
- 检查不改变既有七天发布门槛，不加蔬菜或蛋白配额，不声称膳食健康达标。
- 页面行为：后台周刊编辑页加载已保存专题时自动调用检查接口；服务端同版本命中缓存。保存后如果已有结果的 `topicVersion` 落后，页面标记为 `stale`，重新加载当前检查后展示新结果。草稿未保存的本地变更不作为服务端检查输入。
- 权限：统计读取/重建和菜单检查均要求 `AdminBearerAuth + SUPER_ADMIN`。检查 GET 可更新派生缓存；缓存是可重建结果，不写管理员业务审计。

## 业务流程与页面行为门禁

### 业务流程

- 用户目标：
  - 在首页点进“本周灵感”后，快速看到本期运营推荐的几道菜，先收下想安排的菜，再一次性安排到同一顿饭里。
- 触发条件：
  - 首页右上固定卡为“本周灵感”专题入口。
  - 或用户在专题页里点击往期推荐卡片。
- 主成功路径：
  - 进入专题页 -> 查看专题头图、类别、描述、本期推荐菜谱 -> 未加入“我的菜谱”的菜先加入 -> 已加入的菜点击“加入计划”进入待安排 -> 点击底部入口打开安排 sheet -> 选择日期和餐次 -> 待安排中的菜一次性写入同一个计划餐次。
- 失败 / 阻断路径：
  - 当前没有任何已发布专题时，专题页展示空态。
  - 指定 `topicId` 不存在时，专题页展示失败态并可返回。
  - 专题存在但某道推荐菜谱已不可曝光时，该菜从专题列表中自动过滤，不阻断整个专题读取。
- 结束状态：
  - 用户停留在专题页继续浏览，且待安排中的菜已经写入同一天同一餐次。
- 确认人 / 确认记录：
  - 当前对话已确认：专题页参考社区编排感，但不做社区能力；“本周灵感”不是泛灵感列表，而是独立运营专题页。

### 页面行为

- 页面入口：
  - 首页右上固定卡。
  - 专题页内部“往期推荐”横滑卡片。
- 展示内容及用途：
  - 头图区：模糊背景、封面、专题名、推荐类别、期次/更新时间、一句描述。
  - 本期菜单：按选中日期展示当天可公开菜谱；日期导航只列出仍有可公开菜谱的日期。
  - 周刊日期范围展示在摘要区；往期卡片横向滑动，并显示各期日期范围。
- 用户操作：
  - 点击某道菜，进入菜谱详情。
  - 点击单道菜或“加入计划”，打开加入计划菜单；当前日期的菜单可批量加入同一计划餐次。
  - 切换日期后只展示所选日期的菜谱；首次进入本期按已确认规则选择日期，往期默认周一。
  - 点击往期卡片，切换到对应专题。
- 加载 / 空态 / 失败态：
  - 首屏 skeleton。
  - 无专题空态。
  - 指定专题不存在或读取失败时显示失败态。
- 成功后的页面变化：
  - 读取成功后显示专题详情。
  - 菜加入待安排后，卡片状态改成“待安排”，底部入口展示当前数量。
  - 提交安排后，当前待安排队列清空，计划数据写入同一天同一餐次。
- 本流程不需要的页面数据：
  - 评论、打卡、话题标签、作者信息、关注关系、专题收藏关系、专题互动计数。
