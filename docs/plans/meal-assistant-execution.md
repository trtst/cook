# 功能执行单：美食助理

## 目标

- 本功能要跑通的最小业务闭环：
  - 在菜谱页进入单菜助理，优先查看固定的助理步骤，缺失时降级到原始菜谱步骤。
  - 在计划/饭局详情页进入本餐助理，先固定菜单，再生成并固定本餐助理。
  - 沉浸式做饭默认优先读取助理步骤，允许切回原始菜谱步骤。
  - 系统菜谱在后台上传时预生成单菜助理；用户菜谱在保存后按需生成，缺失太多时允许实时补洞。
- 对应 V1 范围：
  - 本功能是做饭执行增强，不改写原始菜谱主数据。
  - 本功能服务单菜执行和一桌菜统筹，不扩成通用 AI 平台。
- AI 仅用于单菜助理生成与补洞，不参与用户每次点击的常规主路径。

  - `Phase 2` 第一段：系统菜谱固定版本已在后台写路径同步生成单菜助理快照，菜谱详情返回可选 `assistant`，单菜做饭模式已优先读取 `assistant.steps`，缺失时回退 `content.steps`。
  - `Phase 2` 第二段：系统菜谱单菜助理已补齐基础运维闭环。后台详情页可查看助理状态、最近尝试时间、尝试次数、最近错误和当前可用快照，并支持手动重新生成；系统菜谱新建、编辑、导入发布和审核收录四条写路径即使助理生成失败，也不再回滚主菜谱版本写入，而是把失败状态和错误信息持久化下来供后台重试。
  - `Phase 3` 第一段：用户私房菜已新增按需生成单菜助理接口；发布成功后可立即生成，私房菜详情进入做饭模式前也可先生成；免费用户会明确走“按原步骤继续”的降级提示。
  - `Phase 4` 第一段：本餐助理生成逻辑已改为优先读取每道菜固定版本上的单菜助理快照，再按 `PREP / COOK / SERVE` 与 `EARLY / MID / LATE` 做规则编排；缺少单菜快照的菜仍会回退原始步骤与时长字段，不阻断整桌生成。
  - `Phase 4` 第二段：本餐缺少单菜助理达到阈值时，会员会在生成本餐助理前自动补齐缺失菜的单菜快照；免费用户不自动补齐，但会在本餐提醒里明确看到“当前先按原步骤保守编排”。

## 业务流程与页面行为门禁

### 业务流程

- 用户目标：
  - 单道菜时，拿到更清晰的执行步骤。
  - 一桌菜时，拿到固定菜单下可直接照着做的执行顺序。
- 触发条件：
  - 菜谱详情页点击单菜助理。
  - 计划/饭局详情页点击做饭助手。
- 主成功路径：
  - 系统菜谱：后台预生成单菜助理 -> 前台直接读取 -> 本餐助理规则编排 -> 进入沉浸式做饭。
  - 用户菜谱：保存后可提示生成单菜助理 -> 进入助理时读取现有快照 -> 缺失太多时实时补洞 -> 生成并固定本餐助理。
  - 未手动确认菜单时，首次点击本餐助理 -> 自动固定菜单 -> 生成本餐助理。
- 失败 / 阻断路径：
  - 非会员不可新生成助理，但仍可查看原始步骤或已固定结果。
  - 单菜助理缺失且当前不满足实时补洞条件时，降级展示原始菜谱步骤。
  - 本餐助理生成失败时，菜单固定状态不回滚。
- 结束状态：
  - 单菜助理按固定菜谱版本持久化。
  - 本餐助理按固定菜单状态持久化。
  - 到达开饭时间后，footer 进入“分享回忆”态，不要求手动确认结束。
- 确认人 / 确认记录：
  - 2026-08-19 当前 Codex 会话内逐项确认。

### 页面行为

- 菜谱页：
  - 入口：单菜助理。
  - 默认展示：优先助理步骤，缺失时原始步骤。
  - 用户操作：查看助理、切回原始步骤、进入沉浸式做饭。
- 计划/饭局详情页：
  - 入口：本餐助理。
  - 菜单未固定时：可添加菜单、确认菜单、发起饭局/快捷分享、我带菜。
  - 菜单固定后：进入可开始做饭态，主家可点击做饭助手。
  - 到时间后：主操作收口为分享回忆。
- 沉浸式做饭：
  - 默认优先读助理步骤。
  - 可切回原始步骤。
  - 不持久化切换偏好。

## 已确认产品结论

### 1. 能力定义

- 美食助理是同一个产品能力，分单菜助理和本餐助理两层。
- 计划和饭局视为同一种本餐记录；饭局只是计划的富化态。

### 2. 挂载与持久化

- 单菜助理快照绑定固定菜谱版本。
- 本餐助理快照绑定本餐记录。
- 单菜助理每个固定菜谱版本成功生成一次并固定。
- 本餐助理每个固定菜单状态成功生成一次并固定。
- 同一 key 重复请求直接返回同一份成功结果。
- 同一 key 首次生成失败时，不算生成成功，可后续重试。

### 3. 系统菜谱与用户菜谱

- 系统菜谱在后台上传时预生成单菜助理。
- 用户菜谱保存成功后进入可生成助理状态。
- 保存成功后可给轻提示：
  - `生成做饭建议`
  - `稍后再说`

### 4. 生成策略

- 单菜助理主要由 AI 生成。
- 本餐助理默认走“读取单菜快照 + 规则统筹编排”。
- 实时 AI 只做补洞，不做默认主路径。
- 实时补洞阈值建议固定为：
  - 缺失菜数 `>= 2`
  - 或缺失占比 `> 40%`

### 5. 菜单固定

- 本餐助理生成前提是菜单已固定。
- 菜单状态只分：
  - `草稿菜单`
  - `已固定菜单`
- 未手动确认菜单时，点击生成助理自动执行“固定菜单 + 生成助理”。
- 菜单固定后禁止修改结构性内容：
  - 换菜
  - 增删菜
  - 调整顺序
  - 改份数
  - 切换到别的菜谱版本
- 菜单固定成功要提示并通知饭局成员。
- 助理生成失败不回滚菜单固定状态。

### 6. 可改但不重生成的内容

- 开饭时间
- 餐次

这些字段只影响时间展示，不影响做饭流程结构，不触发本餐助理重生成。

### 7. 编辑影响

- 用户私房菜编辑后形成新菜谱版本。
- 旧版本单菜助理继续保留。
- 已固定本餐若仍引用旧版本，不受后续编辑影响。

### 8. 降级规则

- 单菜助理缺失时，降级到原始菜谱步骤。
- 本餐助理部分缺失时：
  - 有单菜助理的菜用助理步骤
  - 没有的菜用原始步骤
- 整桌都缺失时，退回基础做饭模式，不给助理编排建议。

### 9. footer 展示状态

只保留 4 种前端口径：

- `菜单编辑中`
- `可开始做饭`
- `已到时间`
- `已取消`

其中：

- `菜单编辑中`
  - 主家：`发起饭局/快捷分享`、`添加菜单`、`确认菜单`
  - 普通用户：`快捷分享`、`我带菜`
- `可开始做饭`
  - 主家：`快捷分享`、`做饭助手`
  - 普通用户：`快捷分享`、`我带菜`
- `已到时间`
  - 主操作：`分享回忆`
- `已取消`
  - footer 隐藏

### 10. 取消能力

- 保留取消计划/饭局接口和状态。
- 当前版本不把取消放进 footer 主操作。
