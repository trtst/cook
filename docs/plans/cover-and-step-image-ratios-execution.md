# 封面与步骤图比例改造执行单

## 目标

- 已有封面文件不重写；菜谱列表/详情、专题和餐桌话题封面展示容器统一为 `3:4` 并由页面裁切显示。“最近看过”列表、文章列表/详情、饭局列表和饭局详情头图保留 `4:3`；饭局回忆分享海报封面区也为 `4:3`。
- 新上传或替换的菜谱、文章、本周灵感专题和餐桌话题封面裁剪并保存为 `3:4`；饭局封面上传裁切并保存为 `4:3`。
- 普通步骤图和 Wiki 步骤图默认 `3:4`，可选择 `1:1`、`16:9` 或原尺寸；饭局回忆分享海报里的封面区域为 `4:3`。
- 计划不新增独立封面能力；计划内引用的菜谱图片随菜谱封面比例改造。

## 本轮范围

- 小程序：菜谱封面/步骤裁剪，菜谱与文章列表/详情展示，饭局封面上传与展示，饭局回忆海报。
- 后端 API：菜谱、文章、运营专题/话题、饭局上传图片的比例处理或校验；Wiki 候选回填比例处理。
- 后台管理：系统菜谱/步骤与 Wiki 候选、普通文章封面、本周灵感专题、餐桌话题上传及预览。
- 文档：菜谱图片规则、内容图片接口契约及本变更记录。

## 本轮不做

- 不修改头像、食材缩略图、勋章图、登录弹窗图、首页快捷入口图片、背景图比例。
- 不改变文章正文图片比例。
- 不新增计划独立封面字段或上传入口。
- 不批量裁剪、重存或替换已有图片文件。
- 官方消息封面不按普通文章封面处理。

## 业务流程与页面行为门禁

### 业务流程

- 用户目标：上传封面或步骤图片时选择/使用约定比例；各页面在容器中统一展示封面比例。
- 触发条件：新建、编辑、替换菜谱/文章/专题/话题/饭局图片；生成并回填 Wiki 步骤候选。
- 主成功路径：前端裁切或服务端按已选比例处理 -> 服务端安全校验与压缩 -> 现有图片主事实引用新对象 -> 所有页面按对应比例展示。
- 失败/阻断路径：不支持或损坏的文件、超大小/像素限制、上传冲突时保留原图与当前引用，提示失败。
- 结束状态：新封面文件为 `3:4`；新步骤/Wiki 步骤按已选比例或原尺寸保存；既有文件仍保持原样。
- 确认人/确认记录：用户在本任务对话中确认比例、页面范围、旧图处理和不新增计划封面。

### 页面行为

- 页面入口：既有菜谱编辑/后台菜谱编辑、内容编辑、专题/话题编辑、饭局详情和图片生成工作台。
- 展示内容及用途：菜谱、专题和餐桌话题封面卡片按 `3:4`；菜谱详情头图按 `3:4`；“最近看过”列表、文章列表/详情头图、饭局列表封面、饭局详情头图和饭局回忆分享海报封面区继续按 `4:3`；步骤图按图片实际保存比例展示。
- 用户操作：封面使用 `3:4`；步骤图和 Wiki 步骤图使用默认 `3:4`，可选 `1:1`、`16:9`、原尺寸。
- 加载/空态/失败态：保留原图片加载、空态、取消、失败及重试行为。
- 成功后的页面变化：即时预览新图片，现有保存/回填确认流程不变。
- 本流程不需要的页面数据：计划封面上传状态、个人背景图和其他未纳入的图片配置。

## 契约与数据边界

- API 字段变化：步骤/Wiki 生图请求使用 `aspectRatio=3:4|1:1|16:9|ORIGINAL`，省略时默认 `3:4`；后台内容图片上传新增必填 `scene=ARTICLE_COVER|OTHER`，仅普通文章封面场景由服务端裁成 `3:4`。菜谱封面尺寸由客户端裁剪结果表达，其他已确认的封面在各自现有链路按比例处理。
- 数据表：不新增。
- Migration：不需要。
- 计划封面：确认不存在独立业务能力，不新增字段或接口。
- 存量图片：保留原对象；页面只设置 CSS 宽高比并裁切显示。
