# 饭搭子生命周期实施计划

## 状态

- 产品规则：已确认并入档。
- 代码实现：未开始。
- API/DTO/数据库 v0.2：待契约和迁移评审。
- 本计划不授权直接修改旧 v0.1 Schema 或 SQL。

## 权威输入

1. `docs/dining-group.md`
2. `docs/configuration.md`
3. `docs/api-contract.md`
4. `docs/technical.md`

`docs/cook/` 和 `docs/plans/dining-group-rename-plan.md` 是历史来源；冲突时不得覆盖上述当前规则。

## 当前不做

- OCR、AI、小票识别。
- 冰箱、计划、购物和饭局独立图片。
- Pro、多家庭、多饭搭子切换。
- 主理人转让。
- 为 Reserved 能力提前建通用中心或占位服务。

## 阶段一：契约与迁移设计

1. 盘点当前 `DiningGroup`、成员、邀请、Recipe、MealPlan、Shopping、订阅和媒体真实实现。
2. 设计 v0.2 状态机、权限矩阵、DTO、错误码和幂等边界。
3. 设计原空间、迁入任务、迁出快照、参与关系、口味快照、菜谱派生关系、技术快照引用、空间账本和清理任务。
4. 明确 v0.1 到 v0.2 的新 migration；不覆盖 `docs/cook/` 的 v0.1 Schema/SQL。
5. 更新 OpenAPI、`packages/domain` 与 `packages/api-client` 后再允许三端开发。

验收：目标接口与当前已实现接口状态分开；没有猜测字段或双写兼容链。

## 阶段二：统一空间与长期关系

1. 注册时自动创建单人饭搭子。
2. 落地唯一活跃长期饭搭子约束。
3. 邀请接受时冻结受邀人原空间，并原子校验席位和状态。
4. 建立 Free `2` 人与饭搭子 Plus `6` 人的服务端权益解析。
5. 建立主理人、普通成员和受限成员访问矩阵。

验收：不能并发突破成员上限，不能访问其他饭搭子，不能出现两个活跃长期空间。

## 阶段三：迁入、退出与快照

1. 原空间资料清单与选择迁入。
2. 菜谱去重、变体提示和容量预检。
3. 冰箱真实物品确认、计划草稿复制、本人购物需求迁入。
4. 退出恢复、私有固定快照、幂等分批带回。
5. 未来已确认参与与历史饭局白名单视图。

验收：源数据不移动，退出不自动取消已确认参与，快照到期不影响已导入数据。

## 阶段四：菜谱与空间

1. 菜谱广场浏览、收录和固定版本引用。
2. Free/Plus 菜谱数 `50/150` 与 `120/350`。
3. 结构化数据 1 KB 计量、用户图片计量、公共图片豁免和空间账本。
4. Free/Plus 图片处理 `750/1125`、质量 `50/80`。
5. 普通保存不产生用户可见历史；Free 永久删除，Plus 每根最多 2 个直接派生做法与 7 天回收站。

验收：派生做法不能再次派生，同一根并发不能突破 2 个；计量可重算，公共图片不复制，删除释放引用正确。

## 阶段五：会员与降级

1. 个人 Plus、饭搭子 Plus 及作用域解析。
2. 饭搭子 Plus 包含主理人个人 Plus。
3. 现金剩余价值 100% 抵扣的补差升级订单。
4. 到期不静默续费；单人化不自动降级。
5. 成员超额 7 天、空间超额立即只读、30 天资源回收。

验收：支付回调幂等，失败不丢原权益，超额不能继续增长，核心数据不被自动删除。

## 阶段六：饭局与口味

1. 饭局邀请、接受拒绝、点菜和取消参加。
2. 临时参与人白名单权限，不成为长期成员。
3. 用户级口味资料与饭局固定快照。
4. 菜谱口味匹配和永久免费过敏/忌口警告。

验收：临时参与人无法读取冰箱、购物、完整菜谱库和内部计划；敏感资料不泄露。

## 阶段七：非 AI Plus 增强

在基础闭环稳定后，按独立功能单确认精细角色、周期计划、购物分工、高级饭局、提醒、模板、导出和家庭统计。会员页只展示已交付权益。

## 清理任务

逻辑过期必须同步拒绝访问，物理清理由部署环境每日调用独立命令；任务需幂等、分批、可重试、避免多实例重复执行，并记录审计与失败告警。目标 SLA 为逻辑过期后 24 小时内物理清理。

## 上线前最低验证

1. 单人注册、长期加入、原空间冻结和唯一活跃空间。
2. 并发接受邀请与免费/Plus 成员上限。
3. 四类数据迁入、退出和带回。
4. 快照有效期、幂等、到期和重新加入失效。
5. 菜谱数量、空间计量、公共资源复用和图片压缩。
6. Free 永久删除、Plus 派生做法与 7 天回收站。
7. 升级折算、支付失败、成员退出、到期选择和不静默续费。
8. 空间只读、清理恢复、成员受限和权限组合。
9. 饭局临时权限与口味隐私。

每个阶段都必须先更新契约、再实现、再运行最小相关验证；同一问题最多三轮实现与 QA，超过后报告阻塞。
