# 后台图片生成工作台（临时）

## 目标和范围

在 Admin 提供一个按食材或菜谱聚合的临时工作台：筛选缺图内容，选择多个食材/整道菜批量生成缺失位置；列表仍展示该对象全部适用图片位置，管理员可逐张修改提示词、重生、预览和确认替换。

- 食材：系统食材图片。
- 系统菜谱：封面图、正文步骤图和 Wiki 步骤图。
- 个人菜谱：仅 Wiki 步骤图；即使 Wiki 状态为 READY，只要步骤图片缺失仍进入待补列表。
- 生图关键词按食材、食谱封面和食谱步骤分别保存，所有管理员共享；Wiki 步骤与正文步骤共用食谱步骤关键词。初始单图提示词取图片位置已有 `imagePrompt`，缺少时由目标内容生成，保存的对应类型关键词拼入提示词。原食谱通用关键词迁移为封面关键词。
- 列表每页 20 条；勾选菜谱跨页保留，全选仅作用于当前页。可按所选菜谱或单个菜谱一键顺序回填现有候选图；失败候选保留以便重试。
- 当前图片与候选图片并列预览；候选重生成功后删除旧候选临时 OSS 对象，失败时保留旧候选。明确删除候选也删除该临时对象。
- 确认替换写入目标图片 URL。系统菜谱步骤图创建新的不可变 `RecipeContentVersion`；个人菜谱 Wiki 图片走现有 Wiki 导入更新规则。
- 替换/删除候选不删除旧发布图片；固定版本和历史引用仍可能使用旧 URL。
- 方舟请求由 API 设置 1K 分辨率和 JPEG 输出，比例按目标位置确定：食材 1:1，系统菜谱封面 4:3，制作步骤图和 Wiki 步骤图默认 16:9。候选图由 API 自动处理：食材 500×500 且 ≤250 KB；菜谱图片 ≤500 KB；封面裁切为 4:3；步骤图不裁切并保留 16:9。
- 生图请求必须带数字字符串 `Idempotency-Key`；API 按管理员以数据库记录执行每分钟最多 10 次的限流。同键重复请求返回首次候选结果，失败请求需使用新键重试。
- 缺图菜谱筛选由 SQL 在数据库侧判断并分页，应用层只加载当前页菜谱正文/Wiki；候选行通过白名单字段映射后返回。
- 候选替换以独立幂等记录覆盖目标写入和候选行删除，重复请求返回首次替换结果。

## Provider 边界

Admin 只调用 `/admin/image-generation/*`。API 内部定义 `ImageGenerationProvider`，Ark Provider 持有凭据、模型名和供应商请求/响应格式；替换供应商时替换该 Provider 绑定，不改 Admin 页面、候选记录和目标回填契约。`ARK_API_KEY`、`ARK_IMAGE_MODEL`、可选 `ARK_IMAGE_ENDPOINT`、`ARK_IMAGE_RESOLUTION`、`ARK_IMAGE_OUTPUT_FORMAT` 和 `ARK_IMAGE_WATERMARK` 仅配置在 API 服务端。请求固定使用 URL 响应且关闭流式输出，以兼容候选图片暂存流程。

## 持久化和临时数据

- `admin_image_generation_settings` 以单例保存食材、食谱封面和食谱步骤共享关键词。
- `admin_image_generation_candidates` 保存候选目标、正文版本、步骤序号、提示词和 OSS `tempKey`；图片二进制只放既有临时图片 OSS 目录。
- 应用候选后或明确删除时移除候选行和临时对象；重生只在新图生成及暂存成功后替换候选。
- 工作台后续下线时，可移除工作台路由/API/provider 并按部署迁移规范清理候选临时对象，再移除两张专用表。不可连带删除已回填的正式图片。

## 首版验收边界

API/Admin 类型检查和 Prisma schema 校验通过；真实方舟调用、真实 OSS 读写、后台浏览器交互和生产迁移需在具备对应环境后验收。方舟控制台文档在无登录会话时只返回应用壳，Provider 请求字段与目标模型需在配置真实模型后按控制台文档确认。

## 部署执行

服务器先在 `apps/api/.env` 配置 `ARK_API_KEY` 和 `ARK_IMAGE_MODEL`，之后只需执行 `cd /srv/cook && ./deploy.sh`。默认完整发布会拉取代码、安装依赖、应用数据库迁移、构建并重启 API、Worker、Admin 和 Site；API 配置预检不会输出密钥，发布后会检查 `cook-api` 在线状态和本机 `/api/app-config`。如本机健康检查地址不同，可设置 `API_HEALTH_URL` 覆盖；微信小程序上传发布、真实方舟调用和 OSS 操作仍需单独验收。
