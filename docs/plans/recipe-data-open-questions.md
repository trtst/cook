## 四、默认基线说明

当前按以下默认基线执行，不再在本阶段逐条单独确认：

1. `Q1~Q12` 全部先按“当前建议”作为默认口径。
2. 这些口径用于后续执行单、接口设计和实现前评审。
3. 若开发时发现与真实数据、真实契约或真实交互冲突，再单独翻出对应编号复核。

开发前建议优先复核的事项仍是：

1. `Q1 estimatedCalories 派生层归属`
2. `Q2 版本标签返回结构`
3. `Q4 导入工作台补齐范围`
4. `Q12 阶段推进顺序`

## 五、当前建议汇总

为方便后续一次拍板，当前建议收口如下：

1. `estimatedCalories` 只保留在派生层。
2. 版本标签独立挂在分析块返回，不并回正文。
3. 健康标签第一版只读。
4. 导入校对页允许一次性补齐 `baseServings / difficulty / duration / categoryId`。
5. 低置信度标签第一版先统一展示 `needsReview`，不单独开确认入口。
6. 少量“代表值映射”可进入 `CONFIRMED`，但仅限高频且无更精确候选。
7. 近义但不完全同物的食材统一人工复核。
8. 个人食材第一版不进入正式营养映射主链路。
9. 工作台第一版以单条校对为主，不做复杂批量。
10. 系统菜谱后台导入与个人网页导入共用同一套核心校对规则。
11. 低置信度标签第一版只展示，不允许人工确认。
12. 后续严格按总执行计划的阶段顺序推进。
