# 功能执行单：餐桌话题

## 目标

- 本功能要跑通的最小业务闭环：
  - 运营在后台持续新建“餐桌话题”。
  - 小程序首页“餐桌话题”入口进入独立列表页，而不是复用“本周灵感”专题页。
  - 列表页按活动时间倒序展示历次话题，卡片固定展示 `大图 + 标题 + 时间戳 + 参与数`。
  - 用户进入话题详情页点击“参与”后，服务端真实记一次参与，并把参与数回写到详情和列表。
- 对应 V1 范围：
  - 属于首页运营与轻活动曝光闭环；当前只做“查看 + 参与 + 计数”，不扩成评论、打卡、报名审核、排行或通用社区系统。

## 本轮范围

- 小程序端：
  - 新增“餐桌话题”列表页。
  - 新增“餐桌话题”详情页，固定承接参与按钮和参与状态。
  - 详情页可选再跳 H5 / 站内详情内容。
- 后端 API：
  - 新增餐桌话题列表、详情和参与接口。
  - 新增后台餐桌话题管理、状态切换和封面上传接口。
  - 首页快捷入口白名单补餐桌话题列表页，默认“餐桌话题”入口改跳新页面。
- 后台管理：
  - 新增“运营 / 餐桌话题”列表与独立编辑页。
- 共享契约：
  - 新增餐桌话题公开响应、后台响应和写入 DTO。

## 本轮不做

- 不做评论、打卡、点赞、分享回流、榜单、主持人、标签和任何社区关系流。
- 不做取消参与；同一用户只记一次参与。
- 不做话题正文 CMS，不在本轮新增富文本、块编辑器或内容版本系统。
- 不做 H5 内直接写参与；真实参与按钮先固定放在小程序原生详情页。

## 业务流程与页面行为门禁

### 业务流程

- 用户目标：
  - 在首页进入餐桌话题后，先看历次话题，再点进某一期直接参与。
- 触发条件：
  - 首页首屏右下卡配置为“餐桌话题”入口。
- 主成功路径：
  - 进入列表页 -> 按时间倒序浏览卡片 -> 打开某个话题详情 -> 点击“参与” -> 服务端按用户去重写入参与事实 -> 详情页立即显示“已参与”，参与数同步增加。
- 失败 / 阻断路径：
  - 当前没有任何已上架话题时，列表页展示空态。
  - 指定话题不存在或未上架时，详情页展示失败态。
  - 未登录用户点击“参与”时，先拉起登录，再继续参与。
- 结束状态：
  - 用户停留在详情页继续查看，并且当前账号的参与事实已写入。

### 页面行为

- 页面入口：
  - 首页首屏“餐桌话题”卡。
- 展示内容及用途：
  - 列表页：历次话题卡流，固定展示封面、标题、时间、参与数。
  - 详情页：封面、标题、时间、参与数、简介、参与按钮、可选“查看活动详情”入口。
- 用户操作：
  - 点击列表卡进入详情页。
  - 点击“参与”写入真实参与事实。
  - 若后台配置了额外详情目标，可继续跳 H5 或站内页查看活动正文。
- 加载 / 空态 / 失败态：
  - 列表和详情都需要首屏加载态与失败重试态。
  - 无话题时展示页面级空态。
- 成功后的页面变化：
  - 参与成功后，按钮切成“已参与”，详情人数立即更新。

## 接口契约

| 方法 | 路径 | 用途 | 权限 | 幂等 | 版本字段 | 状态 |
| --- | --- | --- | --- | --- | --- | --- |
| `GET` | `/table-topics` | 读取餐桌话题列表 | 公开 | 否 | 无 | 本轮新增 |
| `GET` | `/table-topics/{topicId}` | 读取餐桌话题详情 | 公开，可带用户 token 读取是否已参与 | 否 | 无 | 本轮新增 |
| `POST` | `/table-topics/{topicId}/participate` | 当前用户参与一个话题 | `UserBearerAuth` | 是 | 无 | 本轮新增 |
| `GET` | `/admin/table-topics` | 读取后台餐桌话题列表 | `AdminBearerAuth` | 否 | 无 | 本轮新增 |
| `POST` | `/admin/table-topics` | 新建一条餐桌话题 | `AdminBearerAuth` | 是 | 无 | 本轮新增 |
| `PUT` | `/admin/table-topics/{topicId}` | 更新一条餐桌话题 | `AdminBearerAuth` | 是 | `expectedVersion` | 本轮新增 |
| `POST` | `/admin/table-topics/{topicId}/status` | 切换上/下架状态 | `AdminBearerAuth` | 是 | `expectedVersion` | 本轮新增 |
| `POST` | `/admin/table-topics/{topicId}/image` | 上传或替换封面图 | `AdminBearerAuth` | 是 | `expectedVersion` | 本轮新增 |
| `DELETE` | `/admin/table-topics/{topicId}/image` | 清空封面图 | `AdminBearerAuth` | 是 | `expectedVersion` | 本轮新增 |

## 最小数据表与约束

| 主事实 / 关系 | owner | 必要字段 | 生命周期 | 外键 / 唯一 / Check | 对应真实查询 | 是否复用现有结构 |
| --- | --- | --- | --- | --- | --- | --- |
| `TableTopic` | `PLATFORM` | 标题、简介、封面、活动时间、详情目标、状态、版本 | 新建、更新、上/下架、长期保留历史 | `status + activityAt + id` 索引 | 列表倒序、详情读取、后台列表 | 否 |
| `TableTopicParticipant` | `USER x PLATFORM` | `topicId`、`userId`、创建时间 | 用户首次参与时创建，不支持取消 | `(topicId, userId)` 唯一；双外键 | 参与计数、用户是否已参与 | 否 |

## 范围自检

- 本次满足的用户确认规则：
  - 餐桌话题是新的功能页，不复用本周灵感详情。
  - 列表页固定做历次话题倒序。
  - 参与数来自用户真实点击参与。
- 每个文件为什么必须修改：
  - 待实现后回填到中央变更日志。
- 明确没有顺手加入的功能：
  - 不加评论、打卡、取消参与、报名审核、内容 CMS。
- 因复用未被证明而没有提前增加的抽象：
  - 不抽通用“活动中心”，先只落“餐桌话题”一条线。
