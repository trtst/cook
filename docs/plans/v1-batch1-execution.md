# 炊火记 V1 第一批执行单

## 目标

第一批只跑通这条最小闭环：

`首页看到下一顿 -> 选菜 / 存菜 -> 看缺什么 -> 写入当前采购清单`

本批只做：

1. 首页下一顿决策
2. 菜谱主系统
3. 冰箱与采购

本批不做：

- 做饭执行
- 饭局轻协作
- 营养展示
- 菜品知识底座增强

## 一、前置条件

| 前置项 | 实现目标 | 如何验证 |
| --- | --- | --- |
| 首页状态口径 | 后端统一返回 `status enum + 摘要数据`，前端不做业务兜底 | 抓接口返回和页面展示逐项对照；页面只按枚举渲染 |
| 当前采购清单口径 | 明确默认清单、聚合规则、来源保留规则 | 从菜谱、计划、饭局进入缺口后，结果写入同一张当前采购清单 |
| 系统菜谱入口语义 | 所有系统菜谱入口统一为 `保存为私房菜` | 详情页、列表快捷操作、搜索结果快捷操作文案与行为一致 |

## 二、模块执行项

### 模块 1：首页下一顿决策

#### 要做什么

- 首页状态卡收口
- 首页动作区固定
- 首页冰箱匹配推荐接真实数据
- `COMPLETED` 归档到最近安排

#### 实现目标

- 首页首屏只围绕“今晚吃什么？”展示当前状态和下一步动作
- 动作区默认基线顺序为：
  - `随机一桌`
  - `看冰箱`
  - `购物清单`
  - `加菜谱`
- 实际排序延续现有逻辑，由后台配置决定；如配置缺失，前端按默认基线顺序兜底
- 首页展示 2-3 道真实可做菜
- 已完成餐次不占首页主位

#### 依赖什么

- 首页状态接口
- 冰箱匹配规则
- 冰箱匹配结果接口或聚合结果

#### 如何验证

- `NO_ARRANGEMENT / NEED_GAP_CHECK / NEED_SHOPPING / READY_TO_COOK` 四个主状态展示正确
- 点击四个入口，分别进入对应页面；后台调整排序后，前端展示顺序随配置变化
- 冰箱推荐按匹配率排序；同匹配率优先私房菜；缺 3 种以上不推荐
- `COMPLETED` 只出现在最近安排，不占首屏状态卡

### 模块 2：菜谱主系统

#### 要做什么

- 系统菜谱统一 `保存为私房菜`
- 保存后进入个人可编辑链路
- 私房菜可加入计划
- 草稿限制加入计划

#### 实现目标

- 系统菜谱进入个人链路只有一条主路径
- 用户可以顺畅完成：
  - `灵感 -> 保存为私房菜 -> 加入计划`
- 草稿菜谱不能安排下一顿

#### 依赖什么

- 保存私房菜接口
- 加入计划接口
- 私房菜 / 草稿状态

#### 如何验证

- 系统菜谱详情页主按钮、列表页快捷操作、搜索结果页快捷操作均显示 `保存为私房菜`
- 点击后进入保存 / 编辑流程，保存成功后在私房菜里可见且可编辑
- 选择餐次后成功生成计划项
- 草稿状态下加入计划按钮受限或拦截正确

### 模块 3：冰箱与采购

#### 要做什么

- 缺口分析统一入口
- 所有缺口统一写入当前采购清单
- 手动项和系统项并存
- 完成购物回写冰箱
- 饭局采购边界收口

#### 实现目标

- 从菜谱、计划、饭局进入时，看到同一套缺口逻辑
- 所有缺口默认写入当前采购清单
- 手动添加的食材和缺口写入的食材可以共存
- 采购完成后可正确回写冰箱
- 饭局只看主家菜单缺口，不带入我带菜

#### 依赖什么

- 缺口分析接口
- 写入购物清单接口
- 当前采购清单聚合规则
- 完成购物 / 入库接口

#### 如何验证

- 从菜谱详情、计划详情、饭局详情进入缺口页时，相同菜单下显示的缺口项一致
- 从任一入口加入后，结果都进入同一张当前采购清单
- 手动添加的食材和缺口写入的食材在同一清单中合并显示；手动项不会被缺口写入覆盖；缺口项不会因手动操作丢失
- 完成后冰箱数量或状态正确变化
- 从饭局进入采购时，不出现我带菜项

## 三、执行顺序

### Step 1

先落前置口径：

- 首页状态接口
- 当前采购清单口径
- 保存为私房菜统一语义

### Step 2

并行开发：

- 首页状态卡 + 动作区 + 冰箱推荐
- 系统菜谱保存为私房菜
- 缺口分析统一入口 + 当前采购清单写入

### Step 3

联调顺序：

1. 首页状态接口联调
2. 首页冰箱匹配联调
3. 系统菜谱保存为私房菜联调
4. 私房菜加入计划联调
5. 缺口分析联调
6. 当前采购清单写入联调
7. 完成购物入库联调

## 四、第一批稳定出口

只有下面 3 条全部成立，第一批才算稳定：

1. 首页能正确引导用户下一步
2. 系统菜谱能顺畅保存为私房菜并加入计划
3. 缺口能正确写入当前采购清单

只要有一条没成立，就不开第二批。

## 五、当前不讨论的项

- 做饭助手增强
- 我想吃池 / 我带菜 / 饭局菜单确认
- 营养展示
- 菜品概念归一
- 搜索聚合增强
- 语音、AI、实时协作

## 六、一句话结论

第一批先把：

**首页状态收口 + 系统菜谱进入个人链路 + 缺口写入当前采购清单**

做成一个能联调的最小闭环。
