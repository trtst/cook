# 通知中心与提醒设置执行单

## 一、目标

- 跑通当前 V1 已确认的站内消息最小闭环：
  - `系统审核消息`
  - `系统清单协作消息`
  - `系统提醒消息`
  - `系统官方消息`
- 将“通知中心”“提醒设置”“后续微信订阅消息”三者职责拆开，避免当前页面继续承诺未落地能力。

## 二、本轮范围

- 小程序端：
  - `pages_me/recommend` 通知中心
  - `pages_me/reminder` 提醒设置
  - `pages/me` 通知中心入口文案
- 后端 API：
  - 新增当前用户自有 `notification-settings / notification-badge / notification-feed-read` 接口
  - 继续复用现有真实来源，不新增独立消息表
- 后台管理：
  - 实现系统官方消息后台发送与发布入口
- 共享契约：
  - 本文档冻结站内消息 V1 范围
  - 微信订阅消息仅列待确认清单，不进入实现

## 三、本轮不做

1. 不新增独立消息表、消息中心聚合表或消息明细持久化迁移。
2. 不接微信订阅消息、不申请模板、不落平台授权逻辑。
3. 不把提醒设置做成“大而全”的消息订阅配置中心。
4. 不做定向人群发送、定时发送、推送统计或已读回执。

补充说明：

- 本轮新增的是“当前用户提醒偏好 + 当前用户未读徽标 + 当前用户通知中心已读游标”这组 user-owned 接口。
- 通知中心可见消息列表仍继续复用各真实来源读取，不在本轮扩成单独的聚合明细接口。

## 四、已确认产品口径

### 4.1 通知中心

- 通知中心是单一时间流列表。
- 所有消息按时间倒序混排。
- 每条消息固定展示 `类型标签 + 标题 + 描述 + 时间`。
- 有落地页的消息点击跳转；没有落地页的消息默认只读。

### 4.2 提醒设置

- 提醒设置页保留。
- 只管理长期提醒偏好，不管理全部消息订阅。
- 当前保留：
  - 饭点提醒
  - 食材临期提醒
  - 每日推荐提醒

### 4.3 微信订阅消息

- 本轮不实现。
- 待消息模板和字段确认后，再从具体业务动作触发订阅授权。

## 五、站内消息 V1 真实来源

### 5.1 系统审核消息

- 个人食材推荐审核结果
- 单位建议审核结果

来源：

- `recipeApi.listIngredientRecommendations`
- `recipeApi.listUnitRecommendations`

### 5.2 系统清单协作消息

- 购物清单协作邀请
- 邀请已接受
- 邀请已拒绝
- 邀请已撤回

来源：

- `shoppingApi.listInvites("ALL")`

约束：

- 清单协作消息继续复用 `shopping_list_invites` 这一套真实事实，不新增第二套消息状态。

### 5.3 系统提醒消息

- 食材临期提醒
- 近期计划提醒

来源：

- `fridgeApi.getSummary(days)` 返回服务端统计的 `expiringCount + latestTime`
- `homeApi.getWeekOverview` 返回服务端给通知中心排序用的 `notificationTime`

### 5.4 系统官方消息

- 后台创建官方消息草稿
- 后台发布官方消息
- 通知中心混排官方消息
- 有正文链接时跳内嵌 H5
- 无正文链接时跳站内官方消息详情页

来源：

- 后台复用 `site_contents` + `OFFICIAL_NOTICE` 栏目
- 小程序读取 `/site-contents/official-messages`

## 六、本轮明确不承诺的消息

### 6.1 微信订阅消息

当前仅冻结待确认范围，不在页面里承诺已开通。

## 七、微信订阅消息待确认清单

### 7.1 建议接入的订阅消息类型

1. 审核结果通知
   - 食材推荐审核结果
   - 单位建议审核结果
   - 菜谱投稿审核结果
2. 清单协作通知
   - 收到清单协作邀请
   - 邀请被接受
   - 邀请被拒绝
3. 计划与清单提醒
   - 计划到点提醒
   - 计划到期提醒
   - 清单到期提醒
4. 冰箱与推荐提醒
   - 食材临期提醒
   - 每日推荐提醒

### 7.2 建议触发时机与展示文案

#### 7.2.1 审核结果通知

1. 食材推荐审核通过
   - 触发时机：后台审核通过食材推荐后
   - 订阅授权建议时机：用户提交食材推荐成功后
   - 标题建议：`食材审核结果通知`
   - 主要文案：`你推荐的食材「{ingredientName}」已审核通过`
   - 补充文案：`现在可以在系统食材里直接使用了`
   - 落地页：`/pages_me/ingredient-units/index?tab=ingredient`
2. 食材推荐审核未通过
   - 触发时机：后台审核拒绝食材推荐后
   - 订阅授权建议时机：用户提交食材推荐成功后
   - 标题建议：`食材审核结果通知`
   - 主要文案：`你推荐的食材「{ingredientName}」未通过审核`
   - 补充文案：`原因：{reviewNote}`
   - 落地页：无强制落地页，可回通知中心
3. 单位建议审核通过
   - 触发时机：后台审核通过单位建议后
   - 订阅授权建议时机：用户提交单位建议成功后
   - 标题建议：`单位审核结果通知`
   - 主要文案：`你建议的单位「{unitName}」已审核通过`
   - 补充文案：`现在可以在系统单位里直接使用了`
   - 落地页：`/pages_me/ingredient-units/index?tab=unit`
4. 单位建议审核未通过
   - 触发时机：后台审核拒绝单位建议后
   - 订阅授权建议时机：用户提交单位建议成功后
   - 标题建议：`单位审核结果通知`
   - 主要文案：`你建议的单位「{unitName}」未通过审核`
   - 补充文案：`原因：{reviewNote}`
   - 落地页：无强制落地页，可回通知中心
5. 菜谱投稿审核通过
   - 触发时机：后台审核通过菜谱投稿后
   - 订阅授权建议时机：用户提交菜谱投稿成功后
   - 标题建议：`菜谱审核结果通知`
   - 主要文案：`你投稿的菜谱「{recipeTitle}」已审核通过`
   - 补充文案：`现在可以查看对应落地页`
   - 落地页：菜谱落地页
6. 菜谱投稿审核未通过
   - 触发时机：后台审核拒绝菜谱投稿后
   - 订阅授权建议时机：用户提交菜谱投稿成功后
   - 标题建议：`菜谱审核结果通知`
   - 主要文案：`你投稿的菜谱「{recipeTitle}」未通过审核`
   - 补充文案：`原因：{reviewNote}`
   - 落地页：无强制落地页，可回通知中心

#### 7.2.2 清单协作通知

1. 收到清单协作邀请
   - 触发时机：发起人成功邀请协作者后
   - 订阅授权建议时机：用户进入通知中心或清单协作页时预先引导；也可在被邀请人首次处理协作消息后提示订阅
   - 标题建议：`清单协作通知`
   - 主要文案：`{ownerName} 邀请你一起维护清单「{listName}」`
   - 补充文案：`点击查看并决定是否加入`
   - 落地页：`/pages_pantry/list-detail/index?listId={listId}`
2. 邀请被接受
   - 触发时机：被邀请人接受清单邀请后
   - 订阅授权建议时机：发起人创建并分享清单成功后
   - 标题建议：`清单协作通知`
   - 主要文案：`{actorName} 已加入你的清单「{listName}」`
   - 补充文案：`现在可以一起维护这份清单了`
   - 落地页：`/pages_pantry/list-detail/index?listId={listId}`
3. 邀请被拒绝
   - 触发时机：被邀请人拒绝清单邀请后
   - 订阅授权建议时机：发起人创建并分享清单成功后
   - 标题建议：`清单协作通知`
   - 主要文案：`{actorName} 暂未加入你的清单「{listName}」`
   - 补充文案：`你可以稍后再次邀请`
   - 落地页：`/pages_pantry/list-detail/index?listId={listId}`

#### 7.2.3 计划与清单提醒

1. 计划到点提醒
   - 触发时机：计划的 `scheduledAt` 到点前固定窗口
   - 订阅授权建议时机：用户创建或保存计划成功后
   - 标题建议：`计划提醒`
   - 主要文案：`你的计划「{planTitle}」快到时间了`
   - 补充文案：`记得按时准备这一餐`
   - 落地页：计划详情页
2. 计划到期提醒
   - 触发时机：计划当日结束前或过期前固定窗口
   - 订阅授权建议时机：用户创建或保存计划成功后
   - 标题建议：`计划提醒`
   - 主要文案：`你的计划「{planTitle}」今天即将过期`
   - 补充文案：`如需继续执行，可及时调整安排`
   - 落地页：计划详情页
3. 清单到期提醒
   - 触发时机：购物清单到期前固定窗口
   - 订阅授权建议时机：用户创建清单或设置到期时间成功后
   - 标题建议：`清单提醒`
   - 主要文案：`清单「{listName}」快到期了`
   - 补充文案：`记得及时采购或调整清单内容`
   - 落地页：`/pages_pantry/list-detail/index?listId={listId}`

#### 7.2.4 冰箱与推荐提醒

1. 食材临期提醒
   - 触发时机：存在临期食材且达到提醒窗口时
   - 订阅授权建议时机：用户在提醒设置里打开“食材临期提醒”时
   - 标题建议：`食材临期提醒`
   - 主要文案：`你有 {expiringCount} 样食材快到期了`
   - 补充文案：`记得优先安排，减少浪费`
   - 落地页：`/pages_pantry/index/index`
2. 每日推荐
   - 触发时机：用户开启每日推荐且到达设定提醒时间
   - 订阅授权建议时机：用户在提醒设置里打开“每日推荐提醒”时
   - 标题建议：`每日推荐提醒`
   - 主要文案：`今天为你准备了新的吃饭灵感`
   - 补充文案：`打开看看今天适合安排什么`
   - 落地页：`/pages/home/index`

### 7.3 建议字段

每条订阅消息至少需要：

- `templateType`
- `title`
- `thing`
- `time`
- `statusText`
- `pagePath`
- `bizId`

按类型补充的业务字段建议：

- 审核结果通知：
  - `reviewType`
  - `reviewResult`
  - `reviewNote`
- 清单协作通知：
  - `listId`
  - `listName`
  - `actionType`
  - `actorName`
- 计划与清单提醒：
  - `planItemId`
  - `listId`
  - `planDate`
  - `mealSlot`
- 冰箱与推荐提醒：
  - `expiringCount`
  - `recommendScene`

## 八、范围自检

- 本次满足的用户确认规则：
  - 先实现站内消息
  - 系统官方消息先走站内消息
  - 微信订阅消息先列类型和字段，待确认后再接入
- 每个文件为什么必须修改：
  - `pages_me/recommend`：接入官方消息混排展示
  - `pages_me/official-message`：承接站内官方消息详情
  - `pages/me`：入口文案与真实消息种类保持一致
  - `apps/api`：补官方消息用户侧读取接口与默认栏目
  - `apps/admin`：补官方消息后台发送入口
  - `minor_change_log`：记录本轮实际交付
- 明确没有顺手加入的功能：
  - 微信订阅模板接入
  - 后端消息聚合接口
  - 官方消息定向推送与统计
- 是否还能缩小改动而不破坏需求：
  - 当前已缩到复用现有 content 主事实，只补一个官方消息栏目、两条用户侧读取接口和站内详情页
