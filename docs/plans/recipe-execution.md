## 三、已确认业务流

### 个人创建

```text
新建 -> 基础信息 -> 高级设置 -> 预览/存草稿 -> 发布到我的
```

发布必须校验名称、单选个人分类、`1～20` 人份、难度、时长、至少一个食材和至少一个有效步骤。发布不自动进入灵感。

### 灵感收藏与升级

```text
浏览灵感 -> 收藏固定版本到合集 -> 用于计划或饭局
                         -> 升级为我的并选择分类 -> 编辑
```

收藏和新草稿均占菜谱额度与个人空间。同一道收藏加入多个场景不重复计数。

### 推荐到灵感

```text
本人创建或已编辑的改编菜谱 -> 选择建议平台分类 -> 提交固定版本
-> 人工审核 -> 驳回/撤回/收录 -> 灵感展示
```

未修改的灵感菜谱不能重复推荐。已收录版本更新必须重新审核，旧版本在新版本通过前继续展示。

### 计划与饭局

```text
我的菜谱或只读收藏 -> 固定版本 -> 计划/饭局菜单 -> 按责任人生成个人购物清单
```

草稿不能进入计划或饭局。人数换算只处理精确用量，模糊用量保留原文。

### 页面地图

1. `pages/recipe/index` 继续作为 TabBar 主页面，内部完成“我的 / 灵感 / 合集”切换、搜索、分类、筛选和列表。

### 主页面层级

```text
固定 NavBar：我的 / 灵感 / 合集
搜索框：搜索菜谱、食材，随页面滚动
Sticky 分类区：固定在 NavBar 下方
菜谱列表：两列等高竖卡，使用页面滚动
浮动管理：仅我的/合集显示，滚动隐藏，停止显示
TabBar：固定在页面底部
```

主页面使用页面级滚动，不在内容区再套一个纵向 `scroll-view`。Sticky 的顶部偏移使用真实导航栏总高度，不能写死胶囊或状态栏数值。

三个区域分别维护自己的页面内状态：

1. “我的”维护当前个人分类和列表位置。
2. “灵感”维护当前平台分类、已应用筛选和列表位置；抽屉未应用的临时筛选不污染列表状态。
3. “合集”维护当前个人场景和列表位置。

切换区域后保留本次页面会话中的选择和滚动位置；退出页面后是否恢复不在本轮承诺，避免提前引入持久化状态。

### 列表状态

每个区域都必须具备独立的：

1. 首屏加载骨架。
2. 空状态和对应主操作。
3. 请求失败与明确重试。
4. 下拉刷新。
5. 分页加载、到底提示和重复请求保护。

“我的”空状态引导新建菜谱；“灵感”空状态区分无内容与筛选无结果；“合集”空状态引导去灵感收藏。未确认真实数据前不放示例菜谱冒充结果。

### 录入页面层级

```text
固定 NavBar：新建菜谱 / 编辑菜谱
可滚动基础区：封面、名称、故事、分类、场景、食材、步骤
高级设置入口：打开约 90% 高度的上滑弹窗
固定底部操作：预览、存草稿、发布
```

录入页评审规则：

1. 个人分类和场景均为 Tag 选择面，不展开成长下拉列表。
2. 食材区按结构化行录入食材、精确/模糊用量和单位，不再解析 `名称|用量` 文本。
3. 步骤区按独立步骤组录入，不再按换行拆分；批量图片按选择顺序追加步骤组。
4. 高级设置弹窗维护临时副本；关闭丢弃，保存后才回写主表单。
5. 预览不写正式菜谱；存草稿和发布是不同动作，不能共用旧“创建菜谱”语义。
6. 离开存在未保存修改的录入页时必须提示，具体草稿恢复时机与服务端契约一起冻结。
7. 底部操作区避让安全区，键盘弹起时不得遮挡当前输入项。

### 组件边界

1. 主页面继续负责 Tab、分类、筛选、分页和路由编排。
2. 菜谱卡片、分类 Tag 区、筛选抽屉和浮动管理按钮先作为菜谱页面局部组件，不提升到根共享组件。
3. 食材行、步骤组和高级设置弹窗先留在菜谱分包内，不抽象为通用表单引擎。
4. 现有 `Layout`、`NavBar`、`TabBar`、`Login`、`Empty` 和 `Skeleton` 继续复用；只有真实能力不足时才做最小扩展。
5. 不为三种区域建立三个重复列表页面，也不建立通用 manager、adapter 或 center 层。

### 登录门禁

1. 未登录进入菜谱 Tab 时默认展示“灵感”，允许浏览灵感列表和详情。
2. 进入“我的”或“合集”时触发登录。
3. 点赞、收藏、升级为“我的”和推荐到灵感时触发登录。
4. 匿名接口只读取审核通过且允许曝光的固定版本，不返回个人持有、额度或操作状态。

## 六、候选契约差距

当前 `apps/client/src/apis/recipe.ts` 只支持 `mine/system/all` 列表、基础正文创建编辑、导入、删除和举报，不能表达：

1. 个人分类、个人场景及其排序。
2. 草稿、发布和编辑草稿。
3. 只读收藏、合集、升级为“我的”和再次导入原版。
4. 平台分类、灵感筛选、点赞、收藏统计和推荐排序。
5. 推荐审核状态和固定提交版本。
6. 故事、难度、小贴士、数值基准人数和结构化时长。
7. 系统/个人食材、计量单位、精确/模糊用量和人数换算。
8. 图文步骤组、临时图片和正式图片绑定。

因此不能先修改页面去兼容旧 `scope` 和 `RecipeContentInput`。必须先完成下一阶段的最小契约与数据约束评审，再开始真实页面实现。

## 八、停止条件

出现以下情况时停止实现并重新确认：

1. 现有候选 API 或 Prisma 模型无法表达已确认的固定版本、只读收藏或推荐审核语义。
2. 需要改变 Free/Plus/Pro/Ultra 数量或空间上限。
3. 需要开放评论、关注、用户搜索、排行榜或未确认的公开 UGC 能力。
4. 需要把个人食材、购物清单或冰箱变成饭搭子共享数据。
5. 图片安全、存储计费或审核责任无法形成可验证闭环。

本次评审已确认现有候选 API 无法表达只读收藏、推荐审核、分类/场景和结构化录入，停止条件第 1 项已触发。未完成下一阶段确认前，不开始客户端兼容实现。
