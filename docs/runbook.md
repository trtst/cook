# 工程执行手册

## 目的

本文定义前后端调试、验证与交付的最低执行纪律。

## 仓库启动基线

启动基线需要写，但只写最小闭环，目的是保证接手者或几天后的自己可以快速跑起当前仓库。

建议至少写清以下内容：

1. 前端运行时版本要求。
2. 后端运行时版本要求。
3. 安装命令。
4. 前端启动命令。
5. 后端启动命令。
6. 构建或服务运行命令。
7. 环境变量文件名与最少必填项。
8. 本地接口地址、代理方式或 mock 方案。
9. 提交前最低验证项。

## 环境基线模板

- 前端运行时版本：落到具体仓库时确认，并同步写入 `.nvmrc` 或等效文件
- 后端运行时版本：落到具体仓库时确认，并同步写入 `.python-version`、`requirements.txt` 或等效文件
- 环境变量文件：`.env.development`、`.env.production`
- 接口联调方式：待确认直连、代理或 mock
- 代理配置位置：落到具体仓库后写明具体文件
- 数据源切换方式：写明通过环境变量、配置文件或工厂方法切换

## 提交前最低检查

每次提交前至少确认：

1. 依赖可安装。
2. 前后端都能正常启动。
3. 前端构建或后端服务启动命令通过。
4. 统一返回结构符合约定。
5. 受影响页面的主路径已手动验证。
6. 控制台与服务日志无新增明显报错。

## 调试基线

在给出问题结论前，应先收集：

1. 复现路径
2. 前端可见行为
3. 控制台证据
4. 网络证据
5. 服务端日志或错误摘要

## 排查顺序

1. 确认预期规则或需求。
2. 确认复现路径。
3. 检查前端运行时行为。
4. 检查网络请求与统一返回结构。
5. 检查服务端日志、错误码与数据流阶段。
6. 运行时画像清晰后，再回到代码。

## 最低验证要求

### UI 改动

需验证：

1. 视觉结果
2. 布局稳定性
3. 相关时的相邻状态

### 交互改动

需验证：

1. 点击、输入、切换或导航行为
2. 成功路径
3. 相关时的失败或阻断路径

### 数据改动

需验证：

1. 请求结构
2. 响应消费方式
3. 兜底行为

### 后端改动

需验证：

1. 参数校验是否明确。
2. 返回结构是否统一。
3. 错误码是否明确。
4. 数据源切换是否仍可工作。
5. 日志是否保留必要摘要而未泄露敏感信息。
6. 文件读取场景是否仍限制在安全目录内。
7. 配置与密钥是否仍通过环境变量或本地忽略配置读取。

## 分支检查清单

以下情况在相关时要显式检查：

1. 空状态
2. 错误状态
3. 加载状态
4. 登录态与未登录态
5. 返回导航
6. 重复交互
7. 参数错误
8. 资源不存在
9. 服务异常
10. 数据源切换
11. 文件读取越界

## 交付说明

一份合格的交付说明应包含：

1. 改了什么
2. 为什么选择这个方案
3. 验证了什么
4. 还剩什么风险或缺口
5. 是否影响前后端接口协议或数据源行为
